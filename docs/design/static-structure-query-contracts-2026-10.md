## Projections inside the same authority

- Q3's `InvocationTarget` follows a lone reference row through carriers as well as transparent references, using
  the same conclusive row selection and formation-cycle gates. Namespace projection still stops at a carrier.
  Its result preserves the terminal context and the last written hop for diagnostics. Transporting this metadata
  is an ordinary `Read` equation, not `Follow`; no successor is speculated under Unknown. Shared tails are query
  entries, with no independent invocation memo or hop limit in production consumers. Q8 alone processes the endpoint
  and its owning bodies. Production consumers use this projection; the legacy route is deleted.

The original seven-family key catalog is too coarse to name distinct equations that the actual semantics needs.
`StaticQueryProjection` extends key identity *within* the same query family and engine:

- Q1's `OpenHeadBinding` is the owner walk for callable open heads. It excludes the never-called program root's
  phantom bindings while retaining its properties and the prelude. Ordinary binding/reference classification keeps
  those inputs. This preserves the established `ParameterOwnership.CallableBindings` rule; it is not a new exception.
- Q3's `MemberSelection` identifies the declared member before chasing that member's structure. It is distinct from
  `Receiver`, which answers the resulting structural capability. A selected runtime member still has a declaration;
  treating its unknown namespace as a missing declaration loses Q8's refinement candidate.
- A Q3 Runtime fact can carry the terminal written reference recipe's scope. This scope is NOT a static namespace or
  runtime target identity. Transparent prefixes transport it, while dynamic member steps discard it. Q8 uses it to
  ask whether processing an `.Algorithm` recipe adds invocation parameters, making it a calculation. This refinement
  never feeds back into Q1–Q7. `StructureCell` must reject Runtime even when its recipe scope is present.

- Q1 separates the owner-only walk, opened-name search and inference availability. This prevents both consulting
  opens too early and manufacturing a trivial self-dependency for every ordinary free name.
- Q3 separates target-cycle verdicts, row-target selection and receiver structure. `A = B; B = { public X = 1; A }`
  demonstrates why a carrier cannot simply be an unconditional cycle terminal. Conversely transporting B's cycle
  answer as A's structure would lose M4★ identity. These are separate equations, not separate structural authorities.
- Receiver expansion has its own Q3 cycle projection. `F(v)=0; A=A.F; P=A.x` has no cyclic input classification:
  receiver expansion returns to A, then `.F` is a structural miss, so A is a calculation and P infers x. Waiting for
  the final member target before declaring any edge leaves a spurious ordinary SCC. The expansion recipe selects the
  first transparent body that must be expanded, navigating already-known carrier members without expanding them.
  It records whether members remain pending. Every committed edge is the entire successor of the expansion-cycle
  question, after ownership and own-input eligibility are decided. A pending-member return proves that member lookup
  misses; bare prefixes still transport the resulting calculation's identity (`A=B.F; B=A` makes B reference A).
  A row ending in the `.Algorithm` intrinsic remains a runtime reference, rather than a calculation namespace.
  This return is distinct from a cyclic target walk; the latter is No in the first witness. This uses the IR-04
  protocol without weakening A1 or conflating inference dependencies with paths.
- Receiver/open-target projections name written expression nodes by reference. They keep dotted navigation work
  shared instead of recursively re-running arbitrary callbacks.
- Range/occurrence projections provide bounded fan-in for large lists and repeated dependencies where needed.

Q2 provider ranges use immutable trees and flatten/deduplicate once, avoiding repeated wide scans as shared reference
tails settle. Q1's name-match ranges can decide known presence/ambiguity before the full list settles. Unknown identity
