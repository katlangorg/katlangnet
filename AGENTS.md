# KatLang Agent Instructions

Shared instructions for AI coding agents (Codex, Claude Code and others) working in this repository. They load on every request, so this file keeps the operating rules and a compact index of the language rules. The full statement of every rule — consequences, examples, implementation map, pinning tests — is in [`docs/design/language-rules/`](docs/design/language-rules/README.md) and is as binding as this file. Before changing a rule's implementation, find its sections through the index entry here or the subsystem map in that directory's `README.md`, and read them, including the **Summary** list that opens many of them. Keep this file short: add detail to the rule documents, not here.

## Ground rules

- `lean/KatLang.lean` is the authoritative language model. The C# implementation in `dotnet/src/KatLang/` stays semantically aligned with it, and Lean wins over implementation convenience, performance or style. Never change language semantics silently or let Lean and C# diverge; if both are wrong for the same bug, fix both together when feasible.
- If Lean is ambiguous for a requested behavior change, stop and ask before implementing.
- Do not invent syntax or semantics that are not in Lean unless the task includes the Lean change. Add no operators, convenience syntax, implicit coercions, hidden fallbacks, duplicated semantic logic or AST simplifications that erase Lean distinctions — least of all to make a local change easier; `.dotCall` and `open` are language constructs, not parser sugar.
- Do not introduce new AST shapes unless strongly justified by Lean or an existing architectural boundary, and preserve the current parser/evaluator/tooling boundaries.
- Reuse the owning logic. Where a rule names THE ONE implementation of a decision, call it instead of re-encoding the rule in another layer, and never reintroduce deleted machinery (§ Deleted machinery).
- Prefer small, reviewable changes that fix the root semantic issue; say so when a change is optimization-only.
- Local tests run only when the user asks for them (§ Validation). Generated artifacts are never edited by hand (§ Generated artifacts).
- A subagent never edits code, tests, expectations or tracked artifacts, runs validation, or stages, commits, resets or discards files.
- `AGENTS.md` is the one agent-instruction file. Do not add `CLAUDE.md`, `CLAUDE.local.md` or `.claude/CLAUDE.md` (Claude Code then stops reading this file), nor other per-tool copies that could drift.

## Making a change

1. **Classify** it with `dotnet/src/KatLang/SEMANTIC-ALIGNMENT.md`, whose "Lean update required?" column is authoritative. Observable semantics need Lean consideration — usually a Lean update plus parity tests. C# implementation or tooling-only changes need C# tests only. Optimization-only changes leave Lean untouched but need equivalence tests against the generic path. Diagnostic wording changes need no Lean when the structured error kind and payload are unchanged. Grammar or AST changes usually need Lean review. Numeric changes route by tier (`evaluator-and-hosting.md` § Numerics). The class decides the required edits only: validation scope is the risk level of § Validation, and an unchanged `.lean` file is no evidence that C# is still aligned.
2. **Read** the relevant rule sections before changing their implementation. Each entry of the compact index at the end of this file names its sections in `docs/design/language-rules/`, as in [`syntax.md` § The spread marker]; the subsystem map in that directory's `README.md` finds the rest.
3. **Change every affected layer in the same task**: Lean; the C# parser, elaboration and evaluator; `dotnet/src/KatLang/Semantics/`; tests and the canonical corpus; `KatLang.ebnf`; `tutorial.md`; the generator guidance. A rule change edits its entry here and its section there together (§ Keeping the system description current).
4. **Add or update focused tests** near the changed layer, with negative coverage where failure modes are meaningful (§ Testing); run them only when the user asks.
5. **Review** the complete diff and `git diff --check`. Report tests as not run unless the user asked for them (§ Validation).

## Keeping the system description current

The system description is the compact index at the end of this file plus the rule files in `docs/design/language-rules/`, `dotnet/src/KatLang/SEMANTIC-ALIGNMENT.md` (Lean/C# classification) and `docs/design/formal-correspondence-ledger.md` (proof status). A task that changes behavior leaves them describing the result, so that the next agent finds the whole system there:

- **A new rule or feature** gets a section in the rule file of its subsystem with its full statement, its implementation anchors (the ONE functions that own each decision) and its pinning tests, and ONE entry in the compact index: its core in a few sentences (aim for under 600 characters) and a pointer to that section. A new subsystem also gets a row in the routing table of `docs/design/language-rules/README.md`.
- **A changed rule** is rewritten in place — the index entry, the section and the **Summary** list that opens it, if any — and the text it supersedes is deleted, not annotated: history belongs in git and in dated design notes, never in current-rule text. When agents might restate the superseded formulation, add it to the stale shapes of `MaintainedDocumentationConsistencyTests`.
- **This file stays short.** Implementation details, examples, test lists, dates and decision history go to the rule section; an index entry changes only when the rule's core changes. Operating rules that every task needs (workflow, validation, testing, generated artifacts) stay here.
- **Before finishing,** reread what you touched: every pointer still names an existing section, nothing contradicts the new behavior, and nothing restates what another section already states.

## Validation

Local test execution is OPT-IN. After an implementation, review the diff and whitespace, but run tests, probe executables, `validate-all.ps1`, `check-cancellation-token-order.ps1`, regeneration runs or Lean builds that execute semantic guards only when the user explicitly asks; an implementation or fix request alone is not such a request. Build-only compilation is allowed. Report tests as not run locally rather than implying that CI passed or asking for permission to run them. The full procedure — levels, commands, manual fallbacks, regeneration, the coverage map — is [`docs/testing-and-validation.md`](docs/testing-and-validation.md); read it before running validation.

### Levels

Classify the COMPLETE candidate (relevant commits plus staged, unstaged, untracked, deleted and renamed files) by regression risk — semantic impact, dependency reach, changed contracts — never by line count, file count or file extension. Record the level and a one-line reason before validation starts; raise it on evidence, never lower it; when the impact cannot be confidently bounded, choose V3.

| Level | When | Scope when validation is requested |
| --- | --- | --- |
| V0 | Prose, comments or formatting proven not to affect execution or mechanically checked content | Review the diff, `git diff --check`, references and consistency; no build or suite |
| V1 | Small, isolated, behavior-preserving refactor or test change | Build the affected dependency closure; run the directly related tests with verified filters |
| V2 | Bounded subsystem behavior; a limited shared helper, API or diagnostic contract | Focused and neighboring suites, the affected builds and the applicable parity/artifact/Lean checks — never the full suite or a `validate-all.ps1` phase |
| V3 | Fundamental, cross-cutting or uncertain changes | One fast-tier .NET phase, one class-filtered `Tier=Slow` run of every touched area, and all seven Lean targets once |

V3 is required for changes to parser or grammar behavior or AST structure, elaboration, name resolution and ownership, parameter binding or implicit lifting, Grace, sequence/list/spread/collect/arity semantics, the evaluator core, the optimizer, sync/async/cancellation behavior, loading and modules, caching and exposure, numerics, Lean/C# correspondence, and broadly reused infrastructure or toolchain — judged by the behavior or machinery changed, not the file touched. V3 always runs all seven Lean targets, even when no `.lean` file changed. Executable documentation (tutorial result claims, spec-linked examples, generated prompt blocks, the EBNF) keeps its verification tests even when only text changed.

### Commands

```powershell
pwsh -NoProfile -File ./scripts/validate-all.ps1 -Phase All
```

`-Phase` is `All` (both phases), `DotNet` or `Lean`; the .NET phase builds the full solution, then runs its test tier (`-Tier Fast` by default). V3 is, in order and against the same unchanged candidate: `-Phase DotNet`; ONE `Tier=Slow` run filtered to the classes the slow-tier bullet below names for every touched area; `-Phase Lean` — so `-Phase All` alone is not V3. A phase already runs every focused suite of its tier: never add a filtered pass over tests the phase's tier already covers for the same candidate. Run the ordinary suite once per unchanged candidate — no second, forced invocation-plan run.

Budgets and limits: `ResourceLimitTerminalityTests`, `BudgetCrossTalkMatrixTests`, `MetamorphicPhase3FamilyTests`, `Q09IndependentHostileReviewTests`. ### Execution discipline

- The primary agent executes validation in ONE stream: never two of `dotnet build`, `dotnet test`, `lake build`, a phase or a regeneration run in flight at once, and never the same suite twice over an unchanged candidate. Do not delegate test execution to a subagent.
- Choose ONE plan per candidate before anything runs, with no pre-validation sweep (it would run every test twice). While editing, when tests were requested, run only the class being written, `scripts/check-cancellation-token-order.ps1` after a signature change, the one previously failing check, the Lean target that compiles an edited file, or a regeneration run.
- Wait for every command to finish: there is no local deadline, so never kill, time-box or restart a run because it is slow, and do not edit the checkout while it runs.
- Write each command's full output to a log (the ignored `artifacts/validation/` directory or a temporary directory), read back only its summary lines, and keep the real exit code.
- On a failure, capture the evidence, repair, rerun only the failing check, then complete the plan for the final candidate; raise the scope one level at a time on evidence, never as a precaution.
- A filter must name real classes, and the summary must show the intended tests discovered AND executed; zero tests is never a pass. Never claim validation from a partial run, a stale build, an unexecuted command or an assumption that CI will pass. Report what ran, the counts, the failures, what was omitted and why, and the log paths; missing tooling is BLOCKED, not a pass.
- Verification outside the script neutralizes inherited `KATLANG_REGENERATE_*` flags for its own process only and must leave the checkout exactly as it started.

## Testing

- Add or update focused tests near the changed layer; cover every affected layer when a change crosses parser, evaluator, semantics or docs boundaries; include negative coverage when failure modes are meaningful.
- **A source-based evaluator test must PARSE CLEANLY and assert the error TYPE.** `Parser.Parse(source).Root` silently discards diagnostics, so use `SourceProvenance.ParseValid(...)` (or `EvaluatorTestSupport.ParseValidRoot`) for ordinary source semantics, `SourceProvenance.ExpectFrontEndError(...)` when the front end is the subject, and `SourceProvenance.ParseAllowingDiagnostics(...)` only where malformed source is the point.
- **Check that an evaluator branch is surface-reachable before writing a source test for it.** Elaboration makes some branches dead; pin those from a prebuilt AST (`EvaluatorDefensiveBranchTests`).
- **A strict allocation assertion** (exactly zero bytes, an exact count, two equal counts) is a `*_GcIsolatedChild` test (`dotnet/tests/KatLang.Tests/Infrastructure/GcIsolatedAllocation.cs`); coarse bounds stay in-process and allow for the ~8 KB counter quantum and `ArrayPool` refills.
- Test design, adversarial coverage, failure analysis and validation belong to the primary agent; a subagent is only for a bulky self-contained investigation, never for running tests.
- Full rules: [`docs/testing-and-validation.md`](docs/testing-and-validation.md) § Writing tests.

## C# implementation rules

- **Plain/counted:** where a pair is semantically equivalent, the COUNTED implementation is canonical and the plain one its value projection (`ProjectCountedValue`; Lean `eval` projects `evalCounted`). Never add an independent plain evaluator body or make a counted function delegate to a plain one; the exceptions are listed in `SEMANTIC-ALIGNMENT.md` § Plain/counted evaluator ownership and its deliberate exceptions. [`evaluator-and-hosting.md` § Plain/counted ownership]
- **Async twins:** every async twin is marked `// MIRROR OF <sync name>` and changes in the SAME change as its counterpart; `TwinNormalizationTests` compares their normalized bodies, and its allowlist only shrinks.
- **Closed hierarchies:** KatLang-owned finite variant hierarchies (`Expr`, `RunResult`, `EvalError`, `Result`, `Algorithm`, `Pattern`, `ParameterPattern`, `ErrorContext` and the internal plan hierarchies) are `closed`. An expression-shaped full-hierarchy dispatch is a switch EXPRESSION with no catch-all arm (a `_` arm survives only as a semantic default); a statement-form `Expr` walk keeps a runtime guard that throws on an unhandled variant, never `default: break`. A new variant satisfies every exhaustive dispatch, is classified in the guarded walks (`AstStructuralPreflight.TryGetExprChild`, `AstWalker.VisitExpr`, …) and gets rows in the behavioral tables (`ExprVariantCatalog`). `OutputFormatter` stays deliberately open. [`evaluator-and-hosting.md` § Traversal exhaustiveness]
- **Payload and state:** the base `Algorithm` has no payload — `User`, `Conditional`, `Builtin` and `Alias` own theirs, and a write narrows to the owning variant (`user with { Opens = … }`). Record-carried state lives in an equality-transparent `RuntimeStateSlot<T>` field, never a side table or a hand-written copy constructor. [`evaluator-and-hosting.md` § Variant-owned Algorithm payload]
- **Balanced state and frames:** budget depth, parser nesting and loader walk state use `readonly struct` scopes disposed from a `using`; calibrated recursive frames (parser, loader, rewriters, evaluator dispatch) hold no span temporaries.
- **Read-only views never hand out their storage:** for published C# values, catalogs, shared elaboration data, host snapshots and result diagnostics, use `SafeReadOnlyCollection.Over` (owned arrays), `OverList` (live library-owned lists) or `Snapshot` (host inputs). Parsed and host-built AST lists keep their own ownership contract (`Algorithm.User.Parameters` is a live projection of the caller-owned `ParameterPatterns`). [`evaluator-and-hosting.md` § Read-only views never hand out their storage]
- **A `CancellationToken` is always the LAST parameter**, internal and private signatures included (several trailing tokens are allowed); a parameter added to a list that ends with a token goes before it (`CancellationTokenParameterOrderTests`). When the user asks for local tests after a C# signature change, `pwsh -NoProfile -File ./scripts/check-cancellation-token-order.ps1` is the first focused check; a selected full .NET phase already includes it, so do not run it separately before that phase.
- **Diagnostics** stay structured, source-positioned, user-friendly and phrased in KatLang terms.

## Language rules — compact index

Each entry states a rule's core and points at its full statement.

### Syntax

- **LEXICAL AND LINE LAW (Q-65, issue #183).** THE CANONICAL NEWLINE RULE: "Newlines separate complete expressions by default. An incomplete expression continues when valid syntax permits it, without consuming a new declaration. Otherwise, an independent expression or declaration begins a new construct. Syntax that cannot stand alone but can legally continue the preceding expression attaches backward. All decisions are syntactic, never based on evaluated values." An attached line-final star (EOF included) is a spread that completes its expression; a detached line-final star is multiplication that leaves it incomplete without consuming a following declaration. Attachment is exact source adjacency (`Parser.IsDirectlyAttached`); LF alone breaks a line; unary `-` must be attached. [`syntax.md` § Lexical identity and physical lines]
- **PARENTHESES GROUP SYNTAX.** A group of exactly one non-spread slot IS that expression (`Parser.IsRedundantGrouping`), so `E ≡ (E) ≡ ((E))` for every semantic observation and no layer may branch on a grouping (the unwrapped node keeps the group's span, a name its identifier span); only several slots or a lone spread survive, as `Expr.Capture`. Pattern delimiters are not grouping: `F((x))` is `SingletonSequencePattern`. [`syntax.md` § Parentheses group syntax]
- **DELIMITERS.** `(...)` groups and delimits arguments, `[...]` builds lists, and only `{...}` and the root open an algorithm scope; a closer is never consumed as junk while a construct is open (#9, `Parser.ExpectCloser`); a character the lexer reported is invisible to the grammar. [`syntax.md` § Delimiters, grouping extent, and unary spans]
- **COMMA AND LINES (SYN-07A, F7).** On one physical line the comma is the ONLY separator (`1 2 3` is `UnseparatedSameLineItem`, and `;` separates nothing); a call follows only a callable reference on the same line; declaration heads are line-local and never an operand of an incomplete line. Parsing never depends on arity, values or types. [`syntax.md` § Comma and same-line items; § Line rules and declaration heads]
- **STAR ROLES.** Prefix COLLECT MARKER (`*name`, binding positions only), postfix SPREAD MARKER (`expr*`, the one spread spelling), the declaration's OUTPUT-SPREADING MARKER (`A* = …`), infix multiplication. `*name` is a COLLECTING BINDING or COLLECTING PARAMETER — never a "variadic parameter", "rest parameter" or "rest binding". [`syntax.md` § Star roles]
- **`open` SYNTAX.** One comma-separated target list per algorithm, before every declaration and row (PV-25); each target is an open form all the way down (PV-11); a plain newline never continues the list; `open 'url'` is front-end load sugar, not a core AST construct. [`syntax.md` § The `open` declaration]
- **OPERATOR PRECEDENCE**, loosest to tightest: `or` < `xor` < `and` < prefix `not` < the ONE comparison tier (`<` `>` `<=` `>=` `==` `!=`) < (`+` `-`) < (`*` `/` `div` `mod`) < prefix `-` < `^` < postfix. Unparenthesized comparisons at one level form ONE chain of adjacent pairs (`Expr.Comparison`): operands are evaluated once, left to right, past a false link and up to the first error, and the chain is never lowered to `and`; `not x > 3` is `not (x > 3)`. [`syntax.md` § Operator precedence, comparison chains, and prefix `not`]
- **STRINGS (STR-03).** A string is raw single-quoted text on one line: no escapes, nothing evaluated. Double-quoted strings and interpolation do not exist and nothing replaces them: outside a comment or a single-quoted string, a `"` starts a rejected run reported once as `UnsupportedDoubleQuotedString` and recovered as a literal that is never a module URL. `.string` is the dot-only number-to-text intrinsic. [`syntax.md` § Strings; `evaluator-and-hosting.md` § String values]

### Ownership, lookup and binding

- **THE RESOLUTION MODEL.** The owner walk (parameter before property per level, the prelude outermost), opens only after the whole walk, promotion only after both, structural-first dot edges, static `open`, identity never spelling. The evaluator's lookups and `ElaboratedScopeLookup` (used by the detector and `Semantics/`) must select the SAME declaration; the owner walk is `ElaboratedScopeLookup.SelectOwnedDeclaration`. [`ownership-and-lookup.md` § The resolution model in one place; § Ownership-first lookup; § The owner walk]
- **CDO-1 CONSUMER-DIRECTED OBSERVATION.** A written name resolves ONE binding without evaluating it, and its immediate consumer demands its VALUE, projects its CALLABLE or invokes it. CALLABLE projection never demands that VALUE; results never gain callable identity; `F()` is a fresh call, never shorthand for `F`; there is no partial application. [`ownership-and-lookup.md` § Consumer-directed observation]
- **BUILTIN CALLABLES ARE ORDINARY PRELUDE BINDINGS (SYN-05).** Resolution selects ONE identity without counting arguments, a nearer binding shadows the prelude completely, and no layer branches on a callee's spelling (only the CALL `load(...)` is recognized by spelling, MOD-07; a bare `load` that nothing binds is `UnboundLoadReference`). [`ownership-and-lookup.md` § Builtin identity and the zero-argument value demand; § The `load` directive and a bare `load`]
- **ZERO-ARGUMENT DEMAND AND LIFTING (Q-03).** A callable satisfies a zero-argument value demand iff a zero-argument call binds it (`Only(*xs) = xs` does, `Head(x, *rest)` does not), and the front end lifts a bare value-position reference only when its callee requires supplied arguments. [`ownership-and-lookup.md` § Zero-argument value demand follows actual call arity]
- **FORWARDING NEVER CHANGES WHAT A NAME REFERS TO (Q-04).** Automatic forwarding reuses parameter bindings only — never properties, opened names, module members or builtins; a name that no PARAMETER binding supplies (a same-named property does not) becomes a new, marked parameter of an inferring body, never of a closed list. [`ownership-and-lookup.md` § Automatic parameter forwarding preserves existing bindings]
- **THE UNIFIED FORMULA-LIFTING LAW.** A formula lifts a reference exactly when its ROLE is a value use (`FormulaLiftingRoles`) and its resolved callable has a lifting signature that requires arguments. Lifting is by binding NAME: each name is supplied once, to every occurrence, from an existing parameter binding of that name or else, in an inferring body, from one new parameter (Q-04). A closed list never gains a parameter — what it cannot supply stays a runtime zero-argument demand — and a bare program-root row naming a callable keeps that callable's own zero-argument demand (THE ROOT CLAUSE; root formulas and blocks written in the row elaborate normally). An inferring formula that would lift a clause family with no lifting signature is `UnliftableClauseFamily`. [`ownership-and-lookup.md` § The unified formula-lifting law; § Formula lifting is by binding name]
- **INFERRED SIGNATURES (X-02).** An inferred signature must be one a programmer could write (`ParameterPattern.FindSignatureViolation`: the singleton rule, one collector per level, no repeated name involving a collecting binding); parameters without output are `ExplicitParametersRequireOutput`. [`ownership-and-lookup.md` § Inferred signatures are held to the rules of written ones]
- **B3-5★ SIGNATURE SELECTION.** Analysis, then one joint SELECTION of every inferred signature (`SignatureSelector`), then a rewrite that never recomposes one: no read observes a provisional signature, so declaration order never changes a selected signature (only diagnostic order follows the rewrite's traversal); a group with no unique grounded answer is `SelfDependentInferredParameters`. [`ownership-and-lookup.md` §§ Signature selection, Recursive parameter inference]
- **STATIC STRUCTURE (ALIAS-UNIFY-1, B3).** Q1–Q7 are the single production structural authority; consumers read completed immutable facts, and an unavailable fact never permits a raw chase. [`ownership-and-lookup.md` § Static structure queries]
- **WHOLE-ALGORITHM TRANSPORT (M4★).** A non-root open body — no written list, not a branch, no parameter of its own after inference — whose one written row is a bare reference to an algorithm of any arity is an alias, unless its static target chase returns to a body it passed (OD-D: then it is an ordinary lazy property). Unbraced `A = P` is a TRANSPARENT REFERENCE (every observation is the target's), `A = { P }` a STRUCTURAL FORWARDING CARRIER (its own structure and members; calls forward freshly); no alias owns a cache entry (OD-E). [`ownership-and-lookup.md` § Whole-algorithm transport]
- **CALLABLE ALIASES AND BARE FORWARDING (FWD-02).** **Do not equate `A(p) = F` with `A(p) = F(p)`: bare forwarding is by compatible existing binding NAME; an explicit call is an ordinary written argument call; formula lifting is a separate by-name inference mechanism.** An open body that WHOLE-ALGORITHM TRANSPORT makes an alias is a CALLABLE ALIAS (binding indirection, `Evaluator.ResolveAliasTarget`); a closed lone-reference body forwards same-named existing bindings only — a collector that nothing supplies receives no argument, a row that then forwards nothing stays the target's bare (cached) read, any other unsupplied parameter is `UnforwardableParameter`, and a target with no forwarding contract is `UnforwardableCallable`. [`ownership-and-lookup.md` § Callable aliases and bare forwarding]
- **RUNTIME-TARGET CALLABLE ALIASES (META-S3-2).** An alias whose row is an enclosing parameter, an argumentless `.Algorithm` link or an argumentless parameter-rooted member path takes its callable from its ONE binding cell (`Evaluator.AliasBindingCell`). A callable target is invoked freshly; a value-only target answers a zero-supply call from its binding cell (never a rerun) and rejects a nonempty one; a projection failure is never read as absence. [`ownership-and-lookup.md` § Runtime-target callable aliases; `call-by-need.md` § Runtime aliases]
- **OPEN, EXPOSURE AND ACCESSIBILITY (K1-08, Q-19, Q-29).** Open-provided names select PUBLIC members and structural dot access DECLARED ones; selection never depends on exposure (select, then ONE check, `Evaluator.IsAccessibleFrom`). Providers count by identity (`OpenProviderIdentity`); a written name reaching several providers at one open level is `AmbiguousOpen`. Every open target must resolve (`UnresolvedOpenTarget`), a target headed by a parameter is `OpenTargetIsParameter`, and inline and module targets are rooted at the prelude. [`ownership-and-lookup.md` § Open, exposure, and accessibility; § Open provider identity; § Static open ambiguity; § Static open-target validity; § Open ambiguity in dependency analysis; § Static-open ownership; § Inline and module open targets]
- **LOADED MODULES (Q-31, Q-32).** A module is a hygienic unit rooted at the prelude, so the load site's names never reach it; one canonical URL is ONE declaration per program. [`ownership-and-lookup.md` § Loaded modules]
- **THE DOT ROUTE (Q-17, Q-75).** For `R.n(args?)`: a declared structural member wins (no receiver is injected; accessibility is checked after selection), a member declared only in branches is `LocalOnlyProperty`, on a structural miss an intrinsic (`.string`, `.Invoke`, `.Arguments`, `.Algorithm`), otherwise the extension fallback `n(R, args)` — structural first at every level of a chain (`ResolveDotReceiver`). On extension fallback `a.F` supplies `a` to `F` and `A*.F` is `F(A*)`; a structural hit introduces no lexical fallback name; inference keeps the written, receiver-first occurrence order (`K = a.t` infers `(a, t)`, `K = t(a)` infers `(t, a)`). [`ownership-and-lookup.md` § Dot-call resolution and missing members]
- **ONE CALLABLE IDENTITY PER DOT EXPRESSION (Q-18).** An argumentless structural path carries its member's callable in every callable position (`Evaluator.ProjectDotPathCallable`); every other dot expression is a value, except `.Algorithm`, the runtime projection of a call reference's captured callee. Math members and host operations are ordinary prelude members in every layer. [`ownership-and-lookup.md` § Math members, host operations, and the prelude in every layer]
- **GRACE AND PARAMETER ORDER (F10, Q-16, X-49, PAR-05).** `~x` / `x~` reorders inferred parameters and is valid exactly on an OWN inferred parameter of its owner (`InvalidGraceMarker` otherwise); a level's own names come first and lifted names follow them. [`ownership-and-lookup.md` § Grace]
- **PARAMETER CHANNELS (EXPORTED-DETACHED).** A bound parameter owns its name on every channel; a captured parameter is read through its lexical owner's activation, and without a usable one every operation on it is `UnknownName`. [`ownership-and-lookup.md` § Parameter channels and shadowing]

### Call-by-need and call references

- **MODEL-C CALL-BY-NEED.** One suspended NeedCell per supplied computation, evaluated at most once on its first VALUE demand (its success, failure or cancellation memoized); CALLABLE projection never forces it. Results are calculation values, never partial applications; never add an observation field to `EvalState`. [`call-by-need.md` § Production implementation map; § Result boundary]
- **CALL REFERENCES (CallReference S1–S2, META-S3-1, META-S3-4).** A `meta` parameter binds the run-scoped plan of a supplied written invocation (capture is inert); `R.Invoke()` re-executes it freshly over its one sticky supply, `R.Arguments` is its lazy read-only view, `R.Algorithm` its one callee cell, and the capture domain is syntactic (`IsPlannableCall`). A reference never leaves its run. [`call-by-need.md` § Call references; § Argument views; § Callable projection; § Generalized capture]

### Sequences, lists, spread and calls

- **OUTPUT BUNDLES AND CAPTURE.** Output is written as expression rows; there is no output keyword. `{...}` is `Expr.AlgorithmExpr` (algorithm identity); a surviving group is `Expr.Capture` over an `OutputBundle` (no identity, no members, not an open target); `Expr.SequenceConstruct` is internal, and the parser never produces it. [`sequences-lists-and-calls.md` § Output bundles, capture, and algorithm identity]
- **ARITY AND COUNT.** `arity` is the structural count of top-level output slots; `count` is the number of evaluated top-level values after the consuming operation opens sequence values (a lazy list of known cardinality is counted without demanding an element, while a `filter` must first discover its matches); they are not interchangeable. `ArityMismatch` reports a cardinality failure (and NEED-04's unequal repeated value), never a wrong kind (Q-27). [`sequences-lists-and-calls.md` § Value boundaries; § Arity error payloads]
- **VALUE BOUNDARIES.** A property, call or builtin result is ONE value (`Result.valueCount`). SELECTION CHOOSES A VALUE, DOT-CALL PASSES A VALUE (on extension fallback `R.F(args)` is exactly `F(R, args)`), SPREAD OPENS A VALUE (one boundary, creating no value); `first(v) ≡ v[0]` for every value. [`sequences-lists-and-calls.md` § Value boundaries; § The dot-call receiver; § Spread semantics]
- **VARIADIC POSTFIX SELECTION (Q-81).** `receiver[s1, …, sn]`, opened on the receiver's line (the colon form is retired): the receiver is demanded once, the selector supply is formed like a call's (explicit spreads run then), and the selectors are demanded and validated left to right; zero selections give `()`, one the value, several one sequence. [`sequences-lists-and-calls.md` § Variadic postfix selection; `syntax.md` § Postfix selection]
- **ARGUMENT ASSEMBLY (X-18, Q-01).** Supply formation is shared by every callable (`FormNeedSupply`, left to right: explicit spreads open then, and each ordinary argument supplies one cell — a parameter reference transfers its existing cell, or fails at once when its binding is unavailable), demand is each callee's own; a slot is evaluated at most once, on its first VALUE demand, and its outcome is final. [`sequences-lists-and-calls.md` § Call argument assembly and written-slot reification; § At-most-once argument value evaluation]
- **LISTS AND STRUCTURAL PATTERNS.** `[...]` lists are never normalized (`[7] != 7`); a sequence pattern matches sequences only and a list pattern lists only, `F((x))` is `SingletonSequencePattern`, and every top-level structural pattern consumes ONE argument whatever it destructures (a top-level collector takes the remaining slice). [`sequences-lists-and-calls.md` § Lists; § Structural patterns]
- **VALUES STAY VALUES — THE EXACT COLLECTOR LAW.** A non-spread argument is ONE item whatever produced it; only `v*` opens it; a collecting binding collects exactly its items as one list (`Coll((1, 2))` is `[(1, 2)]`). Nothing silently spreads a value. [`sequences-lists-and-calls.md` § Collecting parameters]
- **REPEATED NAMES (NEED-04).** Group-aware: callable-bearing occurrences compare by identity, the first value-only one anchors the group, and the binding is never a splice; ONE inspecting binder (`BindNeedPatterns`) serves calls and clause families. [`sequences-lists-and-calls.md` § Collecting parameter lists, deconstruction, and callbacks; `call-by-need.md` § NEED-04]
- **COLLECTION BUILTINS.** Fixed-arity callables with one `collection` parameter (`count(1, 2, 3)` is an arity error). The supply is formed first (explicit spreads run then), cardinality is checked before any ordinary VALUE demand, only executed value and control slots are demanded, and a callback is projected only to invoke it. [`sequences-lists-and-calls.md` § Collection builtins]
- **CALLBACKS, LAZY `reduce`, LAZY COLLECTIONS (Q-25, #203, #204).** A callback result is kept whole. `reduce` demands its whole collection, then `initial` once if it is empty (the reducer is never projected), otherwise only its last step, each accumulator deferred. A list is lazily read positions, so consumers read only what they need (`[10, 1 / 0][0]` is `10`). [`sequences-lists-and-calls.md` § Callback results; § Lazy `reduce` accumulators; § Lazy collections and pipelines]
- **LOOPS (META-S3-3, Q-23, Q-24, Q-26, LOOP-CF1).** `while(meta step)` and `repeat(meta step, count)` take a captured call as step and initial state (`Step(0).while`); a step's patterns bind the incoming state and its rows produce the next state. `while` reads its flag first: `false` returns the incoming state without forming the earlier rows, `true` forms them and the supply minus the flag is the next state (a one-item supply is both flag and next state). A completed loop is ONE value. [`sequences-lists-and-calls.md` § Loops: patterns bind, rows produce, spread opens]
- **DECLARATION-LEVEL OUTPUT SPREADING.** `A* = …` changes no algorithm: the front end spreads every eligible statically resolved call, so a marked program IS its explicit-`*` counterpart. [`sequences-lists-and-calls.md` § Declaration-level output spreading; `syntax.md` § The declaration-level output-spreading marker]

### Evaluator, hosting and diagnostics

- **ELABORATION BOUNDARY.** `Parser.Parse` results are elaborated (raw syntax is `Parser.ParseSyntax`); the passes are INTERNAL, so never re-publicize one or add a partial facade; `Evaluator.Run*` evaluates host-built ASTs as-is. [`evaluator-and-hosting.md` § Elaboration boundary]
- **SOURCE LOADING.** Loading is async-only through `RunOptions.DownloadCode`, every target admitted first (`ModuleLoadTarget`); a load-bearing branch is a deferred unit compiled when selected (MOD-10); module elaboration transforms only directives (PV-02); every front-end error blocks evaluation. The CLI's guarded downloader and its exact stderr lines are a tool contract. [`evaluator-and-hosting.md` § Source loading and deferred modules; `call-by-need.md` § Required source information]
- **DIAGNOSTICS AND LOCATIONS.** `DiagnosticBag` keeps the first N diagnostics, then one marker; every span belongs to its result's document; a missing location is `null`, never a sentinel or `default(SourceSpan)`. A frame the front end synthesized adds no diagnostic frame, and a cell keeps its original source and span for blame. [`evaluator-and-hosting.md` § Bounded diagnostic lists; § One coordinate space per result; § Explicit value-type source locations; § Diagnostic transparency of synthetic frames; § Blame for an output-less written argument]
- **DEPTH, STACK AND DAG SAFETY.** Entry points run the iterative `AstStructuralPreflight` first and recursive walks probe the stack; every front-end pass is DAG-safe — reference-identity memos per region, never an inherited context copied per child or a shared bundle re-walked per edge. [`evaluator-and-hosting.md` § Structural depth and parser budgets; § Shared-DAG guarantee]
- **BUDGETS, LIMITS AND CANCELLATION (Q-02, Q-09, SEC-01, SEC-02).** Budgets are operation-local; a resource limit is terminal for the run; limits never choose a strategy, and every strategy charges identically. Cancellation is never an ordinary failure, non-match or verdict: the public entry throws the original `OperationCanceledException` with its token, and inside an async twin run it travels as the terminal `EvalError.HostTermination` marker (cells keep the retained exception) until the entry rethrows it. [`evaluator-and-hosting.md` § Budgets and cancellation; § Resource limits are terminal for the run; § Limits observe a run]
- **ASYNC AND HOST OPERATIONS.** No Lean counterpart: the sync evaluator is the oracle, an async entry routes once per run by capability, and host operations are prelude properties over `Expr.NativeCall`. [`evaluator-and-hosting.md` § Async evaluation and host operations]
- **ZERO-ARGUMENT PROPERTY CACHE.** A read reuses the value published for its resolved binding and owning invocation (INNER-PROPERTY LIFETIME: every actual call has fresh bindings). Only the outermost successful qualifying evaluation publishes; a re-entrant read evaluates on its own while the entry is empty (Q-37); `A()` is fresh but may establish an empty entry (CACHE-PUB-1); failures are never stored; never weaken an exposure refusal — fix the classification. [`evaluator-and-hosting.md` § Zero-argument property cache]
- **VALUES AND ERRORS.** Lean numerics are `Int` and C# uses `Decimal128` (exact-integer laws change together; Decimal128-only behavior is a pinned divergence); Booleans are a value kind, not numbers. An error names the first contract the operation cannot satisfy: cardinality `ArityMismatch`, a value of the wrong kind `TypeMismatch`, missing callability `NotAnAlgorithm`, a selection naming no position `BadIndex`, a zero divisor `DivisionByZero`, any other domain failure `IllegalInEval`. [`evaluator-and-hosting.md` § Numerics; § Boolean values; § The evaluation-error taxonomy]
- **HOST SETTINGS AND OBSERVATIONS.** Seeded randomness is one run-scoped stream; `MinDecimalPlaces` / `MaxDecimalPlaces` compose per setting by minimum, and an effective minimum above the maximum is an error, never clamped; `tick()` is an ordinary builtin over one run counter. Passive root-property observations are recorded only where the cache publishes, and root output-row counts partition the run's output rows. [`evaluator-and-hosting.md` § Seeded randomness; § Decimal places: minimum and maximum, source and host; § The `tick()` diagnostic counter; § Passive root-property observations; § Root output-row counts]
