# 2. Core KatLang model

KatLang is expression-oriented. Everything is an algorithm. A bare number is an algorithm producing one value. `1, 2, 3` is one algorithm producing three values. Named formulas are properties.

There are no statements, variables, classes, dictionaries, `let`, `var`, `return`, `for`, `foreach`, `lambda`, `fn`, `def`, `class`, `match`, or `=>`. KatLang's own collections are sequence values `(1, 2, 3)` and exact immutable lists `[1, 2, 3]`; do not import foreign array idioms (no `A[0]` indexing, no mutation, no `.push`/`.append`).

Use numeric truth:
- `0` is false.
- Any nonzero number is true.
- Do not generate `true` or `false`.

Property definitions:
    Name = expression

Prefer implicit parameter properties for ordinary formulas. Free identifiers become parameters automatically, so do not add an explicit parameter head merely to restate the same parameters.

Prefer:
    F = a + 1
    F(5)

Avoid:
    F(a) = a + 1
    F(5)

If an algorithm has an explicit parameter list, that list is closed. Names not declared in the parameter pattern must resolve from the surrounding scope; otherwise they are reported as unresolved. Implicit parameters are inferred only for algorithms without an explicit parameter list.

Teaching contrast:
    Add = x + y
    Add(2, 3)

versus:
    Add(x) = x + y
    # error: y is not part of the closed explicit parameter list

Avoid `Name(x) = body` when `Name = body` would infer exactly the same parameter list in the same order and every explicit parameter is used normally.

Zero-parameter property calls have two access modes:
- `Fun` may reuse a cached property-style value during the current evaluation. Use this form when cached property-style reuse is desired.
- `Fun()` bypasses the zero-argument cache for that zero-parameter property itself. It does not recursively force nested property references to bypass their caches. To request fresh nested values, write nested calls explicitly with `()`: `B = A, A` keeps cached/property-style `A` inside `B()`, while `C = A(), A()` asks for fresh `A` values inside `C()`.

Use explicit heads only when they add semantic value:
- a parameter must be intentionally ignored, e.g. `K(a, b) = a`;
- pattern matching / conditional algorithm branches are needed;
- recursive/sequence-value parameter patterns are needed, e.g. `PairSum((x, y)) = x + y` or `CountSequenceValue((*values)) = values.count`;
- literal branch patterns are needed;
- a higher-order callable interface is clearer with named binders;
- a reusable sequence-style helper must capture immediate top-level call items with a collecting parameter, e.g. `Many(*values) = values.count`;
- an algorithm body uses a block structure where the explicit call interface is intentional;
- the user explicitly asks for an explicit callable signature.

Explicit algorithm head:
    Name(x, y) = {
        x + y
    }

Prefer trailing output:
    A = 3
    B = 4
    A + B

Output is written as bare expression rows; output rows may be interleaved with property definitions, and the conventional style is definitions first, output last.

Output shaping:
- Comma `,` creates top-level outputs and ordinary call argument slots.
- Comma `,` and allowed expression adjacency create expression-list slots. `1, 2, 3`, `1 2 3`, and newline-separated `1`/`2`/`3` are all three slots where adjacency is allowed. Root output consumes a bare expression list as output rows; call syntax consumes it as argument slots; parentheses materialize it as one sequence value.
- Semicolon `;` is not supported as expression syntax. Never generate it as a separator or collection constructor. Use comma/adjacency for separate slots and parentheses for one sequence value.
- Expression spreading is the postfix spread star: `value*`, with the star directly attached to a completed expression. A spread evaluates its operand exactly once and contributes the items of ONE item-producing boundary (sequence and list values supply their contained items; an atom or string supplies itself as one item) to the surrounding item supply. A spread RETURNS NO VALUE — the receiver decides what the items become. The same star is the multiplication operator, and the right operand decides, not spacing: any same-line right operand makes the star infix multiplication (`a* b`, `a*b`, and `a * b` all multiply), so write `a*, b` to spread `a` before another same-line supplied item. Line endings disambiguate the same way: `a*` newline `b` is a spread followed by a new row, while a detached trailing star `a *` newline `b` continues as a multiline multiplication. A spread is one whole slot, so `Use(a b*)` means `Use(a, b*)`; use `Use((a, b*))` for one sequence-value argument. A dot may chain after a spread: `x.Calculate*.Target` means `Target(x.Calculate*)` — the spread receiver's items become the leading call arguments, resolved lexically. Repeated attached stars compose through capture (`value**` means `(value*)*`; a multi-item supply is a fixed point, and only a lone structured item opens one more boundary); `value**next` is an error. `spread` is an ordinary identifier — not reserved, not an intrinsic; a call or member access spelled with that name is an ordinary call or member access, never a spread.
- A property/call/builtin RESULT is ONE value (a value boundary). A multi-output body returns one sequence value, displayed on a single row as `(…)`, not as separate rows: `F(x) = x, x + 1` then `F(5)` is `(5, 6)`. Collection-producing builtins (`order`, `orderDesc`, `distinct`, `take`, `skip`, `filter`, `map`, `range`, `atoms`) return ONE exact immutable list value, displayed as `[…]`: `X = 1, 2, 3` then `X.order` is `[1, 2, 3]`. `atoms` recursively collects numeric atoms through both sequence and list boundaries and returns them as one exact list (`atoms(7)` is `[7]`, `atoms([1, [2]])` is `[1, 2]`, `atoms('text')` is `[]`); lists still have no truth value, so an `atoms` result is not an `if` condition. Use an explicit spread star at the call site to re-spread the returned value into separate rows/items (`F(5)*`, `X.order*` — spread opens one returned boundary). This mirrors `if`. A collecting binding stores an exact list, so `F(*a) = sum(a)` works because the builtin opens the bound list after binding, while `a*` explicitly spreads that list for forwarding. List results are EXACT — no singleton or empty erasure: a collection builtin that keeps exactly ONE item returns a one-element list, so `take(((1, 2), (3, 4)), 1)` is `[(1, 2)]`, and zero kept items return `[]` (never `()`) — never generate code assuming the single survivor is unwrapped. NOT value boundaries (still multi-output): root program output (`1, 2, 3` shows three rows), explicit caller-site spread, and `while`/`repeat` loop state. Scalar/reduction builtins already return one value; a `map`/`reduce` callback must still return exactly one element.
- Collection-builtin results index directly: `Sorted = X.order` stores an exact list and `Sorted:0` selects its first element (`range(1, 3):2` is `3`, `[3, 1, 2].order:0` is `1`), so no spread-capture step is needed for `:` indexing. Arithmetic or comparison on a WHOLE list value is still a type error (lists are not operator-transparent and have no truth value) — select an element first (`Sorted:0 + 1`) or spread-capture (`Sorted = X.order*`) when a canonical sequence VALUE is specifically wanted. Terminal builtin steps need no spread-capture: a lone list result supplied as the next builtin's collection is opened one boundary, so pipelines like `range(1, 10).filter(IsEven).sum` keep working.
- Postfix continuations win over adjacency on the same physical line only. A `(` or `{` after a callable name on the same line continues the call even across whitespace: `F (1, 2)` is the call `F(1, 2)`, `A.B (1)` is the dot call `A.B(1)`, and `values.map { n * 2 }` is `values.map{n * 2}`. A physical newline never continues a closed expression into a call: newline-separated `F` + `(1, 2)` is the expression list `F, (1, 2)`, and a `(`- or `{`-led line after a definition body is a following output row, not call arguments for that body. For multiline calls, open the delimiter before the newline (`F(` newline `1, 2` newline `)`); an already-open argument list spans lines normally. Indexing `:` is same-line only — never start a line with `:` (parse error). Postfix grace `~` is same-line only — a `~`-led line is its own prefix-grace row. Never start a line with a binary operator expecting continuation (`A` newline `-1` is the expression list `A, -1`, not subtraction; write `A -` newline `1` to continue arithmetic), and comments never change line-boundary decisions. A `.`-led line is the supported exception and continues the dot-call chain. Prefer the compact `F(1, 2)` style. Non-callable targets never become calls (`2 (3)` is the expression list `2, 3`, not multiplication).
- Public result-window display may separate multiple comma output slots onto visual rows for readability. Visual row separation is presentation only; it does not create semantic groups. Sequence values display as sequence values. `EvaluateToString()` is a separate atom/stringification path and may format output differently.

The empty sequence value is written `()`. It is a real value (displayed as `()`), not `null`, `void`, `false`, a unit value, or a no-output body. `()` is its own visible output slot with zero items. Repeated ordinary parentheses around the empty sequence are redundant grouping and canonicalize to `()`. KatLang does not expose higher-order empty sequence values through `(())` or `((()))`. Only spreading an empty sequence with `()*` contributes zero items; a plain `()` output stays a visible slot.

`{}` is an empty algorithm body with no defined output. It is not a value: using it where a value is required (including comparing it with `()`) is a missing-output error.

Examples:
    A = ()
    A                    # ()
    A.count              # 0

    () == ()             # 1
    () == (())           # 1
    (()).count           # 0
    count((()))          # 0

    B = {}
    B.count              # error: no defined output
    B == ()              # error: no defined output

    IsEven = x mod 2 == 0
    filter((1, 3, 5), IsEven) == ()       # 0: filter returns the empty LIST [], and [] != ()
    filter((1, 3, 5), IsEven) == []       # 1
    filter((1, 3, 5), IsEven).count == 0  # 1: test collection-builtin emptiness with count(...) == 0 or == [], never == ()

Algorithm-level explicit parameters are valid only when the algorithm defines output. If an algorithm is only a container, put callable formulas on its child properties:
    Algo = {
        Prop = x + y
    }
    Algo.Prop(1, 2)

## Collecting explicit parameters

KatLang supports recursive parameter patterns in ordinary algorithm definitions and conditional branch heads. Sequence-value patterns consume one parent-level argument slot. A top-level collecting parameter instead COLLECTS the supplied call argument slots as one exact immutable list. A user function call preserves argument boundaries: it does not implicitly open a single sequence argument, so a plain sequence-valued argument is captured as one supplied argument unless a spread `value*` is written. (Assignment deconstruction is different — it is an unpacking receiver that opens one lone sequence- or list-valued right-hand side before binding.)

Use a prefix star directly attached to an explicit parameter name (`*values`) when a user-defined property should collect the supplied call arguments. "Collecting parameter" is the canonical construct term; "variadic" describes only a callable that has one. A collecting binding COLLECTS the argument slots assigned to it into ONE exact immutable list: zero slots form `[]`, one slot forms `[item]` (never collapsed to the item), many form `[item1, item2, ...]` — with `Collect(*items) = items`, `Collect()` is `[]` and `Collect(1)` is `[1]`. Variadic user callables consume the argument stream as supplied (no implicit opening of a single sequence or list argument). Collection builtins are NOT variadic: they are ordinary fixed-arity callables (`sum(collection)`, `contains(collection, item)`) whose one bound collection argument opens one outer boundary after binding (one lone grouped sequence value OR one lone exact list value is opened as the collection), and every builtin requires its exact call shape:
    Many(*values) = values.count

Rules:
- `*values` parses as parameter name `values` with collecting-binding semantics; the star must be directly attached to the name.
- Prefix `*name` is the ONLY collecting-binding syntax, and it collects ONLY in binding patterns — explicit parameter lists, nested sequence-value patterns, and assignment deconstruction; the marker is never an expression operator: generate `F(*items) = body`, `F(first, *middle, last) = body`, and `first, *middle, last = value` for collecting bindings, and postfix `items*` for spreading. The canonical forwarding idiom is `Forward(*items) = items*.Target`, equivalently `Forward(*items) = Target(items*)`.
- At most one collecting parameter is allowed in each comma-separated pattern level.
- Collecting parameters are explicit only; do not infer them from free identifiers.
- Do not combine a collecting binding with grace `~`.
- A lone collecting parameter `*values` collects the supplied call arguments (the degenerate lone-collecting-binding case): with `Arg = 1, 2, 3`, `Many(Arg*)` and `Many(1, 2, 3)` collect `values = [1, 2, 3]` (count 3), while `Many(Arg)` and `Many((1, 2, 3))` supply ONE grouped argument and collect `values = [Arg]` (count 1) — the argument is NOT opened, and grouped vs spread calls differ for every sequence-, list-, and empty-valued argument (scalar atoms/strings coincide because spread is total). Supply items with an explicit spread `Arg*`. An empty call `Many()` collects `[]`; multiple sibling grouped values are preserved as separate elements unless each is explicitly spread.
- A parameter list with two or more captures that contains one collecting parameter is the general comma deconstruction form of the same item-supply binding. Fixed captures before the collecting parameter bind from the front, fixed captures after it bind from the back, and the collecting parameter collects the matched middle items (possibly zero) as one exact immutable list.
- An item-supply call consumes the supplied argument slots as given. With `Scale(*values, factor) = values.map{n * factor}` and `Arg = 1, 2, 3`, `factor` binds from the back and `*values` collects the front: `Scale(Arg*, 10)` and `Scale(1, 2, 3, 10)` supply three front slots collected as `values = [1, 2, 3]` and return the exact list value `[10, 20, 30]` (use `Scale(Arg*, 10)*` to open it into separate rows). `Scale(Arg, 10)` and `Arg.Scale(10)` supply `Arg` as ONE front slot, collected as `values = [Arg]`, so the numeric `map` callback fails on the sequence element — always spread when the helper needs the items. The plain argument is never opened during binding.
- Forwarding a collected list is ordinary spread: `Forward(*items) = items*.Target` — equivalently `Forward(*items) = Target(items*)` — re-supplies exactly the collected items; `Target(items)` without the spread star passes the whole list as one argument. Inside a helper body, pass the collected list unspread to a collection builtin as its one collection argument (`values.sum`, `count(values)` — the builtin opens the bound list one level); `sum(values*)` is an arity error.
- The same comma binding pattern on the left of `=` is, by contrast, an unpacking receiver (Python-style): assignment deconstruction opens one lone sequence- or list-valued right-hand side before binding, and the collecting target collects its middle items into an exact list. With `A = 1, 2, 3, 4, 5`, `x, *y, z = A` unpacks `A` into `x = 1`, `y = [2, 3, 4]`, `z = 5`; `x, *y, z = A*` supplies the same items, and a direct item supply `x, *y, z = 1, 2, 3, 4, 5` binds the same way. The empty collected segment is `[]` and a singleton segment is `[item]`. This unpacking is assignment-specific — a function call `F(A)` still passes `A` as one argument and needs `F(A*)` to spread it. At most one movable collecting binding is allowed.
- An explicit spread `expr*` happens before binding and supplies ordinary argument slots (spread opens one sequence OR list boundary). For a variadic user callable the spread items join the captured argument stream. Builtins are fixed-arity, so a spread must land on exactly the fixed argument count: with `Values = 1, 2, 3`, `count(Values*)` and `count([1, 2, 3]*)` are three-argument arity errors — pass the value directly (`count(Values)`, `count([1, 2, 3])`) or group the spread (`count((Values*))`).
- A sequence-value parameter pattern consumes one parent-level argument slot and then binds that sequence value's immediate contents.
- A collecting parameter inside a sequence-value parameter pattern consumes siblings only inside that sequence value; it does not collect across outer arguments.
- Nested sequence values are preserved as sequence-value top-level elements; there is no recursive flattening.

Calls preserve argument boundaries; assignment deconstruction unpacks:
    A = 1, 2
    F(*x) = x

    F(A)      # collects A as one supplied argument; displays [(1, 2)]
    F(A*)     # explicitly opens A first; displays [1, 2]

    G(first, *rest) = first, rest

    G(A)      # first = (1, 2), rest = []   (the call does not open A)
    G(A*)     # first = 1, rest = [2]       (the spread star opens A first)

    B = 1, 2, 3
    x, y, z = B      # ok: deconstruction unpacks B into x=1, y=2, z=3
    x, y, z = B*     # also ok: supplies the same items
    x, *y = B        # x = 1, y = [2, 3]    (the collecting binding collects an exact list)

Use collecting parameters for reusable collection helpers:
    PairSum((x, y)) = x + y
    Many(*values) = values.count
    Head(first, *rest) = first
    Tail(first, *rest) = rest
    Init(*init, last) = init
    Last(*init, last) = last
    Scale(*values, factor) = values.map{n * factor}
    Between(*values, minValue, maxValue) = values.filter{n >= minValue and n <= maxValue}
    SequenceValueCount((*values)) = values.count
    Window((first, *middle, last), scale) = first * scale, middle.count, last * scale
    NestedState(((*history, previous), current)) = history.count, previous, current

Important distinction:
    Collect(list) = list          # one ordinary argument boundary
    Collect(*values) = values     # collects the item supply as one exact immutable list
    SequenceValueCount((*values)) = values.count # one sequence-value argument slot, then immediate contents

For `Arg = 1, 2, 3`, `Arg.Collect.count` is `3` with `Collect(list) = list` because `count` later consumes the returned sequence value. With `Collect(*values) = values`, `Collect(Arg).count` and `Arg.Collect.count` are `1` (the stored sequence is ONE collected element, `values = [Arg]`), while `Collect(Arg*).count` is `3` (explicit spread opens the items into separate argument slots first). The old coincidence where grouped and spread variadic calls agreed is intentionally gone.

For `Arg = (1, 2), (3, 4)` and `Many(*values) = values.count`, `Many(Arg)` is `1` because the stored sequence is one grouped argument, while `Many(Arg*)` is `2` because spread exposes its two row values. Do not use `atoms(Arg)` to simulate collecting binding; `atoms` would recursively flatten to four numeric atoms. Use a spread star `value*` only when opening one value into the surrounding item supply; do not generate `content(...)`, which is no longer a builtin.

For `FlatState((*history, previous), current)`, the call shape is `FlatState((1, 2, 3), 4)`. For `NestedState(((*history, previous), current))`, the call shape is `NestedState(((1, 2, 3), 4))`. The extra outer sequence value is semantically significant.

## Display precision (DisplayDecimals)

`DisplayDecimals = n` is a special top-level property that controls how many digits after the decimal point are shown in the displayed result.

- It must be a top-level property (a plain top-level definition, not nested inside another algorithm).
- `n` is an integer from `0` to `99`.
- It applies recursively to every numeric leaf in the displayed output, including structured sequence-value results.
- It is display-only: it does not change stored values, intermediate calculations, comparisons, cached property results, or what `Math.Round` would produce.
- Use it for requests such as "show the result to 2 decimals", currency display, or "round the displayed result to N places".
- Use `Math.Round(value, digits)` instead only when the underlying numeric value (not just its display) must actually be rounded.

Example:
    DisplayDecimals = 2
    (Math.Pi, Math.Exp(1))       # (3.14, 2.72)

Do not invent unsupported display forms. None of these exist:
    value.displayDecimals(n)
    displayDecimals(value, n)
    Display = { Decimals = n }
    Display.Decimals = n

# 3. Naming

- PascalCase for properties and algorithms: `CircleArea`, `Total`, `Step`.
- Lowercase/camelCase for implicit parameters: `price`, `radius`, `itemCount`.
- Single-letter names are fine for conventional math or physics notation.
- Avoid shadowing builtin/prelude names with parameters, binders, or helper placeholders. No name is hard-reserved at the parser level; the builtin/prelude names below are syntactically shadowable, but shadowing them is unsafe because it can break lookup, collection pipelines, or intended builtin calls. Do not generate code that shadows them.

Avoid shadowing these parameter or helper names:
`if`, `while`, `repeat`, `range`, `filter`, `map`, `count`, `contains`, `first`, `last`, `distinct`, `take`, `skip`, `min`, `max`, `sum`, `avg`, `reduce`, `order`, `orderDesc`, `atoms`, `load`, `Math`, and the lowercase Math aliases `pi`, `exp`, `abs`, `ceil`, `floor`, `round`, `sign`, `sqrt`, `ln`, `lg`, `sin`, `asin`, `cos`, `acos`, `tan`, `atan`, `atan2`, `pow`, `log`, `random`, `randomInt`. (`e` is an ORDINARY identifier — there is no `Math.E` constant and no `e` binding; Euler's number is `exp(1)` / `Math.Exp(1)`.)

Use alternatives:
- `total` instead of `sum`
- `itemCount` instead of `count`
- `minimumValue` instead of `min`
- `maximumValue` instead of `max`
- `meanValue` instead of `avg`
- `predicate` instead of `filter`
- `transform` instead of `map`
- `span` or `values` instead of `range`

# 4. Syntax and operators

Arithmetic:
- `+`, `-`, `*`, `/`, `div`, `mod`, `^`
- `/` is true decimal division: `7 / 2` is `3.5`.
- `div` is integer division that truncates toward zero: `7 div 2` is `3`, `-7 div 2` is `-3`.
- `mod` is the remainder; its sign follows the dividend: `-7 mod 2` is `-1`, `7 mod -2` is `1`.
- Choose `/` vs `div` deliberately: use `/` for ordinary (possibly fractional) division and `div` only when an explicit truncating quotient is wanted.

Comparisons:
- `==`, `!=`, `<`, `<=`, `>`, `>=`
- Comparisons return `1` or `0`.
- `==` and `!=` compare values structurally across all value kinds: numbers by value, strings by exact value, and sequence values by length plus recursive element equality. Different value kinds (e.g. a number and a sequence value) compare unequal rather than erroring.
- `<`, `>`, `<=`, `>=` and the arithmetic operators require numeric scalar operands.

Logical:
- `and`, `or`, `xor`, `not`
- Use `not` for logical negation; a lone `!` is not a valid token. `!=` is the not-equal operator.

Operator precedence, lowest to highest:
1. `or`
2. `xor`
3. `and`
4. `==`, `!=`
5. `<`, `>`, `<=`, `>=`
6. `+`, `-`
7. `*`, `/`, `div`, `mod`
8. `^`
9. unary prefix `-` and `not`
10. postfix `.`, `:`, and call application

Associativity and precedence warnings:
- `^` is right-associative: `2 ^ 3 ^ 2` means `2 ^ (3 ^ 2)`.
- The comparison and equality levels are left-associative.
- Unary minus binds tighter than `^`, so `-3 ^ 2` means `(-3) ^ 2` (which is `9`), NOT `-(3 ^ 2)`. To negate a power, write `-(a ^ b)` or `0 - a ^ b`.
- `not` binds tighter than comparison, equality, and the logical operators, so `not x > 0` means `(not x) > 0`. Prefer `not (x > 0)`, or rewrite as a direct comparison such as `x <= 0` or `a != b`.
- Do not chain comparisons. `a < b < c` means `(a < b) < c` (comparisons yield `1`/`0`, so the second comparison runs against `1` or `0`). Write `a < b and b < c` instead.
- Parentheses override precedence; add them whenever the intended grouping differs from this ladder.

Numeric literals:
- Integers and decimals: `42`, `3.14`, `0.5`.
- A decimal needs digits on both sides of the dot: write `0.5` (not `.5`) and `5.0` (not `5.`).
- Digit separators are allowed between digits: `1_000_000`.
- Scientific notation uses a lowercase `e`: `1e6`, `1.5e-3`. Uppercase `E` is not valid.
- Numbers are IEEE 754 Decimal128: 34 significant decimal digits, exponent range about ±6144. `NaN`, `Infinity`, and `-0` are ordinary values (from `Math.Sqrt(-1)`, overflow, etc.); division by a zero-valued divisor is still an error.

Multiple outputs:
    1, 2, 3

Use comma for ordinary multi-result data and argument slots.

Sequence values:
    (left, right)

Parentheses construct one sequence value. Newline and same-line adjacency create expression-list slots, not sequence values. Use parentheses for sequence-shaped output:
    SalaryExpenses(3800, 1, 0)
    ''
    SalaryExpenses(50, 0, 0)

For one sequence value, write:
    (SalaryExpenses(3800, 1, 0), '', SalaryExpenses(50, 0, 0))

Adjacency in a call argument list separates arguments, so `F(1 2)` is the two-argument call `F(1, 2)`. Same-line whitespace between a callable name and its argument list is allowed: `F (1, 2)` and `F(1, 2)` are the same call, and `A.B (1)` is the same dot call as `A.B(1)`. A physical newline never continues a closed expression into a call: newline-separated `F` + `(1, 2)` is the expression list `F, (1, 2)`. For multiline calls, open the delimiter before the newline (`F(` newline `1, 2` newline `)`).

Flat fixed calls preserve expression boundaries. A property reference used as one argument is one argument expression, even if that property evaluates to multiple outputs. Do not pass `Pair` to `Add(x, y)` expecting `Pair = 10, 20`, or a multi-output dot-call result, to fill both parameters. Use separate arguments, explicit indexing, or explicit spread when multi-output results should spread into fixed parameters:
    Pair = 10, 20
    Add = x + y

    Add(Pair)           # invalid: one argument expression
    Add(Pair:0, Pair:1) # OK

    Tail = 2, 3
    Use = a + b + c

    Use(1, Tail)        # invalid: two expression boundaries
    Use(1, Tail*)       # OK: Tail* spreads its items into the b and c slots

Spread (postfix star, directly attached to a completed expression):
    expr*

Expression spreading is the postfix spread star: `expr*`. It evaluates its one operand and contributes that value's immediate items to the surrounding item supply; it returns no value and never materializes a sequence or list by itself. The surrounding receiver decides how to bind, capture, collect, or emit the supply. The same star is the multiplication operator, and the right operand decides, not spacing: any same-line right operand makes the star infix multiplication (`a* b`, `a*b`, and `a * b` all multiply), so write `a*, b` to spread `a` before another same-line supplied item. At a line ending, `a*` newline `b` is a spread followed by a new row, while a detached trailing `a *` newline `b` continues as a multiline multiplication. At boundary-sensitive sites this matters: `Use(1*, Tail)` has argument slots `1*` and `Tail`; use `Use((1*, Tail))` for one sequence-value argument. Prefix `*name` directly attached to a name is the collecting-binding marker, valid only in parameter and deconstruction binding patterns; it is never an expression operator. Repeated attached stars compose through capture (`value**` means `(value*)*`; a multi-item supply is a fixed point, and only a lone structured item opens one more boundary); `value**next` is an error. A dot may chain after a spread: `x.Calculate*.Target` means `Target(x.Calculate*)` (lexical resolution). `spread` is an ordinary identifier — not reserved, not an intrinsic.

The spread star binds to its completed receiver expression before expression-list handling. `Use(a b*)` and `Use(a` newline `b*)` both mean `Use(a, b*)` — the star in `b*` has no same-line right operand, so it is a spread, and `a` is a separate adjacency slot. Comma slots stay structural (`Use(a*, b)` is a two-argument call; `Use(a* b)` would multiply instead). Use explicit parentheses when one sequence value is intended.

Use comma for ordinary multi-result data and argument slots. Do not scatter spread stars as a decorative list separator. Prefer:
    Values = 3, 4, 2, 1
    Values.sum

Use the spread star only when opening evaluated result content is intended and the opened slot count matches the callee (a comma is required before any following same-line item — `A* 3` would multiply):
    A = 1, 2
    A*, 3                 # spread plus a separate slot: 1, 2, 3
    (1, 2)*, 3            # 1, 2, 3
    1*, (2, 3)            # 1, (2, 3) — spreading the scalar 1 yields one item; (2, 3) is a separate slot and stays one sequence value
    ((1, 2))*, 3          # 1, 2, 3 — redundant unary parentheses canonicalize to (1, 2) before the spread opens its items
    ((1, 2), 3)*          # (1, 2), 3 — spread opens exactly one level; the inner pair stays intact

Bare spread does not create a new sequence value, does not preserve or merge properties, and does not recursively flatten nested sequence values. Spreading the empty sequence value, `()*`, contributes no items. A body with no defined output, such as `{}`, is still a missing-output error in spread. Parentheses around spread preserve one sequence-value result boundary.

Do not use spread to merge libraries or open targets:
    open A, B             # OK
    open A*, B            # invalid: spread is not an open form

Do not rely on spread to expose a member like `A.X` through a spread value (a spread returns no value, and a dot chain after a spread such as `A*.X` resolves `X` lexically as a call target, not structurally on `A`). Define or open the property source explicitly.

Exact immutable lists (square brackets):
    [1, 2, 3]
    []
    [[1, 2], [3, 4]]

`[...]` constructs one EXACT immutable list value — a second collection kind, distinct from sequence values. No singleton or empty canonicalization ever applies to list structure: `[7] != 7`, `[[]] != []`, `[] != ()`, and `[1, 2] != (1, 2)`, while ordinary parentheses AROUND a list stay redundant grouping (`([1, 2]) == [1, 2]`). Equality is structural and recursive. `[` always begins a NEW expression — never a call or indexing delimiter, so `A[1]` is the adjacency list `A, [1]` (indexing is `:`). Element slots use the ordinary expression-list model, including spread:
    A = 1, 2, 3
    [A*]                     # [1, 2, 3]
    [0, A*, 4]               # [0, 1, 2, 3, 4]
    [1, []*, 2]              # [1, 2]

The spread star on a list-valued expression opens exactly ONE list boundary (`[]*` supplies zero items, `[[7]]*` supplies `[7]`). Single-name assignment preserves a stored list (`x = A` keeps `[1, 2, 3]`), while `x = A*` captures the canonical sequence `(1, 2, 3)`. Calls never open lists implicitly: `F(A)` passes one list argument; write `F(A*)` to supply its elements. A multi-target deconstruction whose right-hand side is exactly one list opens it (`x, y, z = [1, 2, 3]`), and collecting bindings collect exact lists (`x, *rest = [1, 2, 3]` gives `rest = [2, 3]`). Selection `:` indexes lists positionally: `[1, 2, 3]:0` is `1` under exactly the same zero-based index rules as sequence selection, the selected element keeps its exact kind (`[[1, 2], [3, 4]]:0` is the stored list `[1, 2]`, and chaining selects one level at a time: `[[1, 2], [3, 4]]:1:0` is `3`), and `[]:0` or `[1, 2]:2` is the ordinary out-of-range index error. Collection builtins ACCEPT list values: a lone list bound as the one collection argument is opened one boundary exactly like a lone grouped sequence value, so `count([1, 2, 3])` is `3` and `sum([1, 2, 3])` is `6` (explicit spread supplies ordinary call arguments, so `count([1, 2, 3]*)` is a three-argument arity error — pass the list directly; a nested list inside a collection stays one opaque item: `count((1, [2], 3))` is `3`). Collection-producing builtins (`order`, `orderDesc`, `distinct`, `take`, `skip`, `filter`, `map`, `range`, `atoms`) return exact immutable list values. Prefer sequence values for arity/supply plumbing and lists when exact cardinality/nesting must be preserved as data.

Indexing:
    expr:index

Indexing is zero-based. It selects one top-level item from a sequence or exact list target and projects that selected item's content one level. Nested sequence and list elements are not recursively flattened, and a selected list element is returned exactly as stored.
The index operator projects one level per hop. Use exactly as many `:` selections as the output shape requires.
If a result is a pair/state such as `(candidate, found)` or `candidate, found`, use `:0` or `:1` directly.
For a final accumulator/state from `reduce` or `repeat`, select fields directly too: use `...:1` for the second field of `(n, found)` or `n, found`, not `...:0:1`.
Chain another `:i` only when the previous selection still returns a sequence value. Do not add a defensive `:0` before selecting a known state field.

Examples:
    State = candidate, found
    State:1              # found

    Values = 10, 20, 30
    Values:1              # 20

    Pairs = (1, 2), (3, 4)
    Pairs:0               # 1, 2
    Pairs:0:1             # 2

    Rows = [[1, 2], [3, 4]]
    Rows:0                # [1, 2]
    Rows:0:1              # 2
    range(1, 3):2         # 3

# 5. Parameters and grace

Free identifiers in property bodies become implicit parameters unless they resolve to properties, builtins, or opened names, but only for algorithms without an explicit parameter list. Explicit parameter lists are closed; unresolved names outside the pattern are errors, not extra callable parameters.

Implicit parameter order is first appearance, left-to-right, depth-first:
    Sub = a - b
    Sub(10, 3)

Use grace `~` to adjust parameter order without dummy arithmetic:
- Prefix `~x` moves `x` one position earlier.
- Postfix `x~` moves `x` one position later.
- Repeat tildes for more movement.
- Grace applies ONLY to one bare parameter/name occurrence; attaching it to an
  expression (`(x + y)~`, `f(x)~`, `x.y~`, `[x]~`, `5~`) is a parse error.

Do not use fake arithmetic like `a * 0 + b` to force parameter order.

Example:
    Divide = y / ~x
    Divide(2, 10)

# 6. Parentheses, braces, groups, count, and arity

Parentheses:
- sequence-value expressions
- create sequence values
- preserve one sequence-value boundary around spread, such as `(history*, next)`
- pass call arguments
- wrap multi-output `if` branches
- NEVER contain declarations: `open` and property/function definitions inside `( ... )` are parse errors

Braces:
- create algorithm-valued blocks with their own lexical scope
- the only delimiter that owns declarations: nested property definitions and `open` go here
- free identifiers inside become parameters of that block
- work anywhere an expression-valued algorithm is allowed, including as a call argument

Do not wrap simple property bodies in `{ ... }` or `( ... )`; simple property bodies already own their parameters.

Nested properties:
    Outer = {
        Inner = x + 1
        Inner(5)
    }

Nested property bodies may capture enclosing algorithm parameters by name. If a nested `repeat`/`while` step needs an enclosing value as part of its state, use a distinct state-slot name in the step body and initialize it from the outer parameter. Do not reuse the outer parameter name inside the step, because it will resolve to the enclosing parameter instead of becoming a step-state parameter.

Nested loop state example:
    IsSquarefree = {
        CheckNextFactor = {
            candidate,
            factor + 1,
            if(candidate mod (factor * factor) == 0, 1, hasSquareFactor),
            hasSquareFactor == 0 and factor * factor <= candidate
        }

        CheckNextFactor.while(n, 2, 0):2 == 0
    }

Use `.count` or `count(...)` to ask how many top-level values an evaluated expression denotes:
    A = 1, 2, 3
    A.count              # 3
    ().count             # 0   (the empty sequence value has zero items)
    count(())            # 0
    (()).count           # 0   (redundant grouping canonicalizes to ())
    count((()))          # 0

A sequence value counts as one top-level item among siblings; a LONE grouped value is opened by builtin collection binding:
    U = (1, 2, 3), 4
    U.count              # 2
    T = (1, 2, 3)
    T.count              # 3   (the lone grouped value is opened as the collection)

Do not count no-output bodies (`{}` is not a value):
    {}.count             # error
    count({})            # error

There is no public `.arity` intrinsic and no public `arity(...)` builtin. Do not generate `expr.arity`, `arity(expr)`, or obsolete `length`.

`arity` may be mentioned only as an internal/documentation concept for structural branch validation, not as generated KatLang code.

# 7. Strings

String literals are first-class runtime values written with single quotes:
    'apples'
    'LV'
    'A'

String literal rules:
- Single quotes only; there are no double-quoted strings.
- The empty string `''` is valid.
- There are no escape sequences.
- A string literal cannot contain an embedded single quote and cannot span multiple lines.
- Do not invent double-quoted strings or backslash escapes.

Strings can be passed, stored, returned, compared, and matched in conditional algorithm patterns:
    'a' == 'a'
    'a' != 'b'

String comparison is exact and case-sensitive. There is no implicit conversion between strings and numbers. Arithmetic on strings is invalid. Do not invent string concatenation, substring, search, case-folding, or parsing functions.

Use strings when the user describes named categories, labels, codes, commands, statuses, products, modes, or options. Preserve the user's names instead of inventing numeric encodings.

Good:
    Price('tomatoes') = 1.20
    Price('apples') = 0.80
    Price(other) = 0
    Expense = Price(item) * quantity
    Expense('apples', 3)

Bad:
    Price(1) = 1.20
    Expense(2, 3)

Number-to-string conversion:
    123.string

Only numeric values support `.string`.

# 8. if

Builtin `if` requires three arguments (after explicit spread expansion):
    if(condition, whenTrue, whenFalse)

Condition is numeric. Use `0` for false and nonzero for true.

There is no two-argument `if`. For conditional numeric contribution, use an explicit neutral else value:
    10 + if(x > 0, 5, 0)

Normally generate the three arguments directly. Explicit spread in call-argument position is valid only when the spread value supplies exactly three values: `if(X*)` with `X = 1, 2, 3` opens into the three slots and equals `if(1, 2, 3)`. A non-spread `if(X)` is one argument and is invalid.

For conditional inclusion over sequences, prefer `filter`.

If an `if` branch returns multiple outputs, parenthesize that branch:
    if(flag, (1, 2), (3, 4))

`if` returns the selected branch as one value boundary, so a multi-output property branch such as `X = 1, 2, 3` yields the grouped sequence value `(1, 2, 3)` (emitted count 1), exactly like referencing `X` directly. Use a result spread `if(flag, X, Y)*` to contribute that result as separate output slots.

Prefer `if(...)` for simple numeric/value branching. Prefer conditional algorithms only for literal pattern matching, string/category dispatch, or multi-branch structural behavior. For a single sequence-value input formula, use an ordinary recursive parameter pattern instead.

# 9. Dot-call semantics

Ordinary dot-call is receiver-first call syntax.

For ordinary/user-defined properties:
    A.B(C, D)

means:
    B(A, C, D)

It preserves `A` as one leading argument segment rather than spreading `A`'s outputs into fixed parameters: the receiver never satisfies extra fixed-parameter arity, and a fixed parameter binds the receiver as one value. The one supply rule: a flat top-level COLLECTING parameter allocated the receiver segment consumes the receiver's evaluated top-level supply, so a written group receiver feeds it item by item — `Mean(*Vector) = Vector.sum / Vector.count` supports both `Mean(1, 2, 3)` and `(1, 2, 3).Mean` — while a named property receiver supplies its one stored value (`Arg.Mean` passes `Arg` whole; use `Arg*.Mean` to supply its items).

Examples:
    Add = a + b

    Add(3, 7)      # OK
    (3).Add(7)     # OK

Use direct multi-argument syntax when a fixed-arity property needs several inputs:
    Add(3, 7)

Use dot-call when one scalar receiver is naturally the first argument:
    3.Add(7)

Do not use dot-call to spread a multi-output receiver into fixed parameters. Use `Add(3, 7)`, not a multi-output receiver dot-call.

If a property receives a sequence-valued or multi-output value as one parameter, the receiver stays ONE value boundary; use a spread star inside the body to join its items with siblings:
    A = 1, 2
    KeepBoundary = a, 3
    JoinBoundary = (a*, 3)

    A.KeepBoundary        # ((1, 2), 3)
    A.JoinBoundary        # (1, 2, 3)

If `f` is a structural property of receiver `a`, `a.f(args)` calls it directly without receiver injection. Otherwise lexical fallback injects `a` as the first argument and resolves `f` exactly like the plain callee in `f(a, args)`, including parameters: with `K(a, t) = a.t`, the member `t` calls the algorithm bound to the parameter `t`, exactly like `t(a)`. A parameter of the current algorithm wins over a same-name visible property; a parameter captured from an enclosing algorithm yields to a visible non-builtin declaration. Structural members of the receiver always win before either.

GRACE WITH DOTCALL: `a~.f(args)` is ordinary postfix Grace on the bare receiver name followed by an ORDINARY DOT EDGE; `a.~f(args)` is ordinary dot with prefix Grace on the participating member/fallback occurrence. Base semantic occurrence order is receiver, participating fallback, then written arguments: `K = a.f` infers `(a, f)`, while both graced two-name forms infer `(f, a)` through the ONE general Grace pass. Runtime fallback still invokes `f(a, args)`, but that assembly does not order the enclosing signature. Postfix Grace requires its receiver operand to be one bare name, so `(x + y)~.t`, `f(x)~.t`, `[x, y]~.t`, `5~.t`, and a second `~.` in `a~.t~.u` reject; prefix member Grace remains valid with a compound receiver because it decorates the bare member name. Call arguments are unrestricted (`a~.t(b, c)` and `a.~t(b, c)` infer `(t, a, b, c)`). Grace NEVER changes member selection or any other executable semantics: `Obj~.V` and `Obj.~V` read Obj's structural `V` exactly like `Obj.V` (write `V(Obj)` to reach a lexical `V`), `x~.string` / `x.~string` keep the dot-only intrinsic, `S~.count` / `S.~count` keep the dotted builtin view, and receiver-segment supply is unchanged. A member participates in inference when fallback MAY be selected, but not when structural resolution is certain and not in a CLOSED explicit list. `a ~ .t` follows the ordinary whitespace-insensitive postfix-Grace grammar and therefore has the same inferred order as `a~.t`; prefix member Grace must begin directly after the dot. A grace-marked `open` target is rejected (`open M~.C`).

Collection builtins are ordinary fixed-arity callables such as `count(collection)`, `map(collection, mapper)`, and `take(collection, count)`. Each receives ONE collection object plus its fixed controls; after binding, a single grouped sequence value OR exact list value is opened one outer boundary as the collection (a builtin-collection rule; user function variadics do NOT open a single sequence or list argument). A dot-call receiver fills the collection parameter:
    (1, 2, 3).sum
    (1, 2, 3).count
    (1, 2, 3).first
    (1, 2, 3).last
    count((Values*, 8))
    filter((range(1, 3)*, 4), IsEven)
    take((1, 2, 3), 2)
    Scale(*values, factor) = values.map{n * factor}
    Scale(Arg*, 10)    # spread the items into the collecting parameter; Scale(Arg, 10) binds values = [Arg]
    (1, 2, 3).Scale(10)    # a written group receiver supplies its rows: values = [1, 2, 3], factor = 10
    Values = 10, 20
    Sum(*values, last) = values.sum + last
    Sum(Values*, 7)    # 37: spread opens two value slots, then 7 fills last
    Sum(Values*)       # 30: the back-bound last takes 20, values = [10]
    # Sum(Values, 7) is an ERROR: the unspread Values is ONE collected
    # element (values = [(10, 20)]), which sum rejects.
    Window((first, *rest), factor) = first * factor, rest.count
    (1, 2, 3).Window(10)

Do not describe or use ordinary dot-call as a spread operator.

# 10. Collection and sequence builtins

Prefer collection builtins over `repeat` or `while` when they express the task directly.

A collection builtin takes exactly one collection argument plus its fixed controls. Never generate inline-item calls (`count(1, 2, 3)`) or spread-fed calls (`count(A*)`); pass one value (`X.count`, `count(X)`) or group explicitly (`count((A*, B*))`).

Collection builtins receive one collection object. Use `()` for a canonical sequence, `[]` for an exact list, or receiver-style syntax for concise expressions. After binding, a single grouped sequence value OR exact list value is opened one outer boundary as the collection (a builtin-collection rule that user function variadics do not apply); a wrong argument count is an ordinary arity error:
- `sum(collection)`, `count(collection)`, `avg(collection)`, `min(collection)`, `max(collection)`
- `first(collection)`, `last(collection)`, `order(collection)`, `orderDesc(collection)`, `distinct(collection)`
- `contains(collection, item)`
- `map(collection, mapper)`, `filter(collection, predicate)`, `reduce(collection, reducer, initial)`
- `take(collection, count)`, `skip(collection, count)`

Collection-producing builtins (`order`, `orderDesc`, `distinct`, `take`, `skip`, `filter`, `map`, `range`, `atoms`) return ONE exact immutable list value displayed as `[…]`; the scalar/selection builtins return their scalar or selected value.

The empty sequence value `()` has zero items, so passing it as the collection argument yields the empty result: `count(())` is `0` and `sum(())` is `0`. A call with NO argument is different — `count()` is an arity error; absence of an argument is never an empty collection. `()` is also different from a no-output body such as `{}`; missing output is still an error.

Do not generate `average(...)` or `.average`; the builtin name is `avg`.

Collection builtins bind their one collection argument, then open it one level (a single grouped sequence value or a single exact list value alike, unlike user function variadics, which never open arguments). Nested sequence values stay intact and a nested list stays one opaque item.

A named multi-output property is passed directly as the one collection argument:
    Values = 1, 2, 3
    count(Values)         # 3
    Values.count          # 3
    count([1, 2, 3])      # 3 (a lone exact list opens the same way)
    count(1, 2, 3)        # INVALID: arity error (three arguments)
    count(Values*)        # INVALID: arity error (the spread supplies three arguments)

Generate `sum(Values)`, `order(Values)`, or `avg(Values)` when `Values = 1, 2, 3` is intended as the collection. Never generate inline-item calls (`count(1, 2, 3)`) or spread-fed calls (`count(Values*)`) — both are arity errors.

The dot-call receiver fills the collection parameter, so `Data.filter(Predicate)` is `filter(Data, Predicate)` and `collection.take(count)` supplies the remaining fixed controls. To extend a collection with extra items, group the spread into one collection argument:
    count((Values*, 8))     # 4
    count(Values*, 8)       # INVALID: arity error (four arguments)
    filter((range(1, 3)*, 4), IsEven)

Use a spread star only when the spread items should become exactly that many ordinary argument slots. Prefer parentheses or selection to shape one collection value before builtin consumption:
    count((Values*, 8))     # 4
    filter((range(1, 5)*, 8), IsEven)

When items are literal values, use parentheses for the collection slot:
    count((1, 2, 3))        # 3
    sum((10, 20, 30))       # 60
    take((1, 2, 3), 2)      # [1, 2]
    skip((1, 2, 3), 1)      # [2, 3]

A single grouped collection value — a grouped sequence value or an exact list — is opened one boundary after binding, whatever the call style:
    count((1, 2, 3))      # 3
    T = (1, 2, 3)
    T.count               # 3
    (1, 2, 3).count       # 3
    (1, 2, 3).sum         # 6
    ((1, 2, 3)).count     # 3 (redundant grouping parentheses canonicalize away)
    A = [1, 2, 3]
    A.count               # 3 (the lone list is opened as the collection)
    sum([1, 2, 3])        # 6

Sibling grouped values INSIDE the one collection argument stay separate items; nest grouped values inside the collection to keep each as one item:
    count(((1, 2), (3, 4)))   # 2
    count((1, 2), (3, 4))     # INVALID: arity error (two arguments)

Use `range(start, stop)` for inclusive integer spans; the result is one exact list value (`range(1, 5)` is `[1, 2, 3, 4, 5]`). It ascends or descends:
    range(1, 5)
    range(5, 1)

Prefer builtin-first pipelines:
    IsEven = x mod 2 == 0
    range(1, 10).filter(IsEven).sum

    Square = x * x
    range(1, 4).map(Square).sum

    range(1, 5).avg

Direct consumers:
- `count(collection)` / `collection.count`: number of top-level items
- `().count`, `count(())`, `(()).count`, and `count((()))`: all return `0` (redundant grouping around `()` canonicalizes to `()`); `{}.count` and `count({})` are errors
- `sum(collection)` / `collection.sum`: sum numeric top-level items; empty returns `0`
- `min`, `max`, `avg`: numeric top-level items; non-empty required
- `first`, `last`: return first/last top-level item unchanged; non-empty required
- `order`, `orderDesc`: sort numeric top-level items into one exact list value (`order((3, 1, 2))` is `[1, 2, 3]`); sequence-value, list, or string items are invalid
- `distinct`: remove duplicate top-level items, preserving first occurrence order; returns one exact list value (`distinct((1, 1))` is `[1]`)
- `contains(collection, item)` / `collection.contains(item)`: top-level membership by ordinary equality
- `take(collection, count)` / `collection.take(count)`: first count items as one exact list value (`take((1, 2, 3), 2)` is `[1, 2]`)
- `skip(collection, count)` / `collection.skip(count)`: skip first count items and return the rest as one exact list value (`skip((1, 2, 3), 1)` is `[2, 3]`)

`avg(collection)` / `collection.avg` returns the decimal arithmetic mean of the numeric top-level items (the total divided by the count), so `avg((1, 2))` is `1.5`, `avg((-1, -2))` is `-1.5`, and `avg((1, 2, 3))` is `2`. For numeric values it is equivalent to `sum(collection) / count(collection)` (apart from `avg`'s empty/non-numeric validation), so use `avg` freely for fractional means. Ordinary `/` is decimal division (`7 / 2` is `3.5`), `div` is truncating integer division, and `mod` is the remainder.

Sequence values are preserved as whole top-level items unless selection `:` projects them or a builtin explicitly says otherwise. Use a spread star `value*` to open exactly one outer sequence-value boundary from one value into the surrounding output, argument, or item supply; it does not turn one fixed-call argument expression into several parameters. Do not recursively flatten nested sequence values.

Do not generate `content(...)`; it is no longer a builtin. Use a spread star `x*` when opening a sequence into the surrounding item supply, and use `atoms(x)` only when recursive atom projection is intended.

`atoms(expr)` recursively collects numeric atoms through BOTH sequence and exact-list boundaries (depth-first, left to right) and erases all container structure. It returns ONE exact immutable list — `atoms(7)` is `[7]`, `atoms([1, [2, (3)]])` is `[1, 2, 3]` — while strings and other non-numeric leaves contribute no atoms (`atoms('text')` is `[]`). The result is a list like any other: it has no truth value and is not an `if` condition. Use it only when the user explicitly wants flattening or numeric atom extraction. Do not use it as a default collection-processing tool.

Do not use `atoms` to implement sequence-style user-defined parameters. Use an explicit collecting parameter such as `*values` when the helper should collect the supplied argument slots as one exact list while preserving grouped sequence values as individual elements.

Callbacks:
- `filter(collection, predicate)` or `collection.filter(predicate)`
- `map(collection, mapper)` or `collection.map(mapper)`
- `reduce(collection, reducer, initial)` or `collection.reduce(reducer, initial)`

`filter` predicate must return exactly one atomic numeric truth value (a collection-builtin result is a list, not an atom, so it is invalid as a predicate result).
`map` mapper must return exactly one mapped element; one sequence value or one exact list value is allowed.
Callback items are projected one level, like selecting an item from a top-level sequence; a list item arrives as one opaque list argument. `filter` keeps the original item when the predicate returns nonzero; `map` replaces each item with the mapper output (exactly one element, where one sequence or list value is allowed) and returns the mapped items as one exact list value. Avoid over-wrapping when a simple projected callback parameter is clearer. Callbacks with a collecting parameter collect exact lists like ordinary calls: a single-collecting-parameter map/filter callback keeps each element as ONE collected slot (`[7].map(Collect)` binds `items = [7]`, giving `[[7]]`; `[(1, 2)].map(Collect)` gives `[[(1, 2)]]`), while a multi-parameter flat callback opens a lone sequence element into row slots first and then collects the middle (`[(1, 2, 3, 4)].map(F)` with `F(first, *middle, last)` binds `middle = [2, 3]`, agreeing with `F((first, *middle, last))`). Reduce supplies element and accumulator slots, so `R(*items) = items` collects `[element, accumulator]`, while a reducer collecting parameter before a fixed accumulator observes `[element]`.

`reduce(collection, reducer, initial)` is a left fold called conceptually as `reducer(element, accumulator)`. It takes exactly three arguments — the initial accumulator is required, so `reduce((1, 2, 3), Add)` is a two-argument arity error. The dotted `collection.reduce(Add)` form recognizes a visibly parameterized reducer and adds a targeted missing-initial hint; the plain form remains an ordinary arity error. Every reducer invocation must emit exactly one next accumulator value: a sequence-value result such as `(a, b)` is one accumulator value, but a bare multi-output result such as `a, b` is invalid as a reducer result. Accumulator binding follows the reducer's parameter pattern: a normal parameter receives one structural accumulator value, while a top-level collecting accumulator parameter binds the current accumulator's top-level slots. Preserve a sequence-value accumulator state intentionally with sequence-valued output. When the accumulator is a sequence-value state such as `(n, found)` or `(sum, count)`, select the final fields directly with `:0` and `:1`; do not write `reduce(...):0:1` unless the first accumulator field is itself a sequence value and you really need its second member.

When mapping/filtering sequence-value pairs, define the callback shape explicitly. Use a sequence-value parameter pattern when the callback item should remain one sequence-value argument at the parent level:
    Swap((a, b)) = (b, a)
    map(((1, 2), (3, 4)), Swap)                  # [(2, 1), (4, 3)]

Reduce into a sequence-valued `(total, itemCount)` state with a sequence-value accumulator parameter, then select fields:
    AddToState(item, (total, itemCount)) = (total + item, itemCount + 1)
    State = reduce((10, 20, 30), AddToState, (0, 0))
    State:0, State:1                             # 60, 3

A top-level collecting accumulator parameter binds the accumulator's top-level slots (here building up a sequence-value accumulator):
    Append(item, *history) = (history*, item)
    reduce((2, 3, 4), Append, 1)                 # (1, 2, 3, 4)

Use `reduce` for custom accumulators. Use `repeat`/`while` only for genuine state machines, recurrences, early stopping, iterative search, or algorithms not naturally expressible as a collection pipeline.

# 11. repeat and while

`repeat(step, count, *init)` performs fixed-count iteration. `step` returns the next state. Each explicit init argument becomes one initial state slot. `repeat(Step, 3, a, b)` starts with two slots; `repeat(Step, 3, Pair)` starts with one slot even if `Pair` evaluates to multiple values. Select the needed result with `:index`; for a state `(candidate, found)`, use `repeat(...):1` for `found`, not `repeat(...):0:1`.

`while(step, *init)` or `Step.while(*init)` performs condition-based iteration. The step returns:
    new_state*, continue_flag

The continue flag is the last output. When it becomes `0`, `while` returns the state from before the final step.
Do not put a meaningful state update only in a step whose continue flag is `0`, because that update will be discarded. For search loops, make the step that records a found value continue once, then let the following step stop.

Initial state slots preserve explicit argument boundaries:
    Step.while(x, 0)
    repeat(Step, n, x, 0)
    Step.repeat(n, x, 0)

Sequence-valued or multi-output values used as a single init argument remain one state slot:
    Pair = (1, 2)
    Step.repeat(n, Pair)       # one state slot
    Step.repeat(n, Pair:0, Pair:1)  # two state slots

Step outputs define the state slots for the next iteration by emitted top-level output boundaries. To keep one structured slot across iterations, return a sequence-value step result; multi-output steps intentionally become many next-state slots. `Step = history*, next` emits history's items followed by `next` as multiple next-state slots (the comma is required — `history* next` would be the multiplication `history * next`), while `Step = (history*, next)` groups them into one next-state slot.

Step-state rule (derive the state interface from the step's parameters, not only from free identifiers):
- If the step has an explicit parameter pattern, the loop-state input shape comes from that explicit pattern. A sequence-value parameter pattern consumes one parent-level state slot and binds inside that sequence value; a top-level collecting parameter makes the step variadic and binds the loop state as an item supply, with required prefix/suffix slots and the collecting parameter collecting the matched middle slots as one exact list.
- If the step has no explicit parameter list, the state slots come from its inferred implicit parameters (first appearance, left-to-right; use grace `~` if the natural order differs from the init slot order).
- A fixed explicit signature requires its declared parent-level slots, and an implicit-parameter step requires exactly its inferred parameter count. A top-level variadic signature instead binds the loop state as an item supply: the fixed prefix and suffix slots are required and the collecting parameter collects the remaining middle slots as one exact immutable list. So `Step(first, *middle, last)` is not an exact three-slot interface — `*middle` is not a single required sequence-valued state slot; it accepts additional middle slots (max unbounded) and requires at least as many state slots as the step has parameters (for example `Step.repeat(2, 0, 5, 5, 10)` binds `first = 0`, `middle = [5, 5]`, and `last = 10`).
- The step output must be bindable as the next iteration's state interface.
- For `while`, add one extra final continue flag after the next-state output.
- Captured enclosing names are not loop-state slots (see nested capture below).

Explicit-signature step (valid even though `x` is not a free identifier):
    Step(x) = x + 1
    Step.repeat(3, 0)              # 3

Sequence-value-state step (one sequence-value slot threaded across iterations):
    Step((*history, previous)) = (history*, previous + 1)
    Step.repeat(3, (1, 2)):1       # 5

Variadic-state step (prefix + collecting + suffix bound as an item supply; the collecting parameter collects the extra middle slots as one exact list):
    Step(first, *middle, last) = first + 1, middle*, last + 1
    Step.repeat(2, 0, 5, 5, 10)    # 2, 5, 5, 12

Nested capture: a nested step may capture enclosing algorithm parameters; captured names consume no loop-state slots. Thread a value through the state only when it changes between iterations, must be returned as part of the state, or intentionally participates in the state interface. Avoid reusing an enclosing parameter name as a step-state slot name, because it resolves to the captured enclosing value instead of becoming a new state parameter.
    Outer(limit) = {
        Step = k + 1, k < limit    # k is loop state; limit is captured, not a slot
        Step.while(0)
    }
    Outer(5)                       # 5

Repeat state example:
    # State is (a, b); grace keeps init order as (a, b).
    FibStep = b~, a + b
    FibStep.repeat(10, 0, 1):0

# 12. Conditional algorithms

Conditional algorithms use branch definitions:
    Name(pattern) = body
    public Name(pattern) = body

In definition context, `Name(...) = ...` is a branch definition, not a runtime call.
Public visibility is family-level. For exported APIs, every clause in a same-name family must include `public`; do not mix public and private clauses.

Supported patterns:
- binders: `x`
- repeated binders as equality constraints: `Equal(x, x)` or `SamePair((x, x))`; the first occurrence binds and later occurrences must compare equal without overwriting it
- integer literals: `0`, `1`, `-1`
- string literals: `'apples'`, `'LV'`
- sequence-value/nested patterns: `(1, (a, b))`

Rules:
- Branches are checked top-to-bottom; first match wins.
- Non-selected branches are not evaluated.
- If no branch matches, evaluation fails.
- There is no `when` keyword.
- There is no special `Else = ...` default syntax.
- A fallback is a final catch-all branch with the same outer interface.
- More specific branches must come before broader catch-all branches.
- The pattern is the complete input specification.
- Do not infer extra implicit branch parameters from free names in branch bodies.
- Branch bodies may use only names bound by that branch pattern or normally resolved names.
- Do not use grace `~` in branch patterns.
- All branches of the same conditional algorithm must have the same top-level input arity.
- All branches of the same conditional algorithm must have the same top-level output arity.
- Matching respects sequence-value shape: `F(1, (2, 3))` is not the same as `F(1, 2, 3)`.
- Do not repeat a binder name when any occurrence is a collecting binding; forms such as `F(*xs, xs)` and `F(*xs, *xs)` are unsupported.
- Branch patterns must be unique up to binder renaming, while preserving repeated-binder equality constraints. Renaming binders does not create a distinct branch; duplicate match-equivalent patterns are rejected.

Duplicate vs distinct branch patterns:
    F(x) = 1
    F(y) = 2             # invalid: same pattern shape as F(x) (duplicate branch)

    Equal(x, x) = 1      # repeated-binder equality: matches only when both arguments are equal
    Equal(x, y) = 0      # valid: distinct from the (x, x) equality constraint

Sole recursive capture/sequence-value parameter-pattern clause families elaborate as ordinary algorithms:
    Apply(f) = f(4)
    Pick(x, predicate) = if(predicate(x), x, 0)
    K(a, b) = a
    PairSum((x, y)) = x + y
    CountSequenceValue((*values)) = values.count

A sole parameter pattern with one collecting binder at its own pattern level is also an ordinary explicit-parameter interface, not conditional matching:
    Many(*values) = values.count
    Scale(*values, factor) = values.map{n * factor}
    CountSequenceValue((*values)) = values.count

Use true conditional algorithms for literal/mixed structural matching or named alternatives:
    Price('tomatoes') = 1.20
    Price('apples') = 0.80
    Price(other) = 0

    Expense = Price(item) * quantity
    Expense('apples', 3)

# 13. Math

Every Math member has one predefined lower-camel-case prelude binding pointing to the SAME canonical function, not a copy:
`pi`, `exp`, `abs`, `ceil`, `floor`, `round`, `sign`, `sqrt`, `ln`, `lg`, `sin`, `asin`, `cos`, `acos`, `tan`, `atan`, `atan2`, `pow`, `log`, `random`, `randomInt`
for `Math.Pi`, `Math.Exp`, `Math.Abs`, `Math.Ceil`, `Math.Floor`, `Math.Round`, `Math.Sign`, `Math.Sqrt`, `Math.Ln`, `Math.Lg`, `Math.Sin`, `Math.Asin`, `Math.Cos`, `Math.Acos`, `Math.Tan`, `Math.Atan`, `Math.Atan2`, `Math.Pow`, `Math.Log`, `Math.Random`, `Math.RandomInt`.

There is NO `Math.E` constant and no `e` binding: Euler's number is `exp(1)` / `Math.Exp(1)`, and `exp(x)` / `Math.Exp(x)` is the natural exponential (`exp(0)` is exactly `1`). Never generate `Math.E` or a bare `e`.

Prefer the lowercase aliases in ordinary formulas; they need no `open Math` and never generate one implicitly:
    cos(0.123)
    sin(pi / 2)
    round(sqrt(2), 10)

Keep `Math.X` (`Math.Sqrt(x)`, `Math.Pi`) as the qualified form for disambiguation — for example next to a local definition of the same name. The aliases are prelude bindings, not members of `Math`: `Math.cos(1)` is invalid; inside `Math` only the canonical PascalCase names exist. User definitions shadow aliases (after `sin(x) = ...`, `sin` is the user's callable), and an explicit parameter such as `F(pi) = pi + 1` uses the parameter, not the constant. Avoid alias names as variable or helper names unless shadowing is intended; explicit parameters remain valid.

Do not `open Math` merely to shorten spellings (the aliases already do that). Use `open Math` only when the canonical PascalCase bare names are specifically wanted and readability clearly improves; it exposes only the PascalCase names:
`Pi`, `Exp`, `Abs`, `Ceil`, `Floor`, `Round`, `Sign`, `Sqrt`, `Ln`, `Lg`, `Sin`, `Asin`, `Cos`, `Acos`, `Tan`, `Atan`, `Atan2`, `Pow`, `Log`, `Random`, `RandomInt`.

Multi-argument Math members (always supply every argument):
- `log(value, base)` / `Math.Log(value, base)` is the logarithm of `value` in the given `base`; it is not a one-argument natural log.
- `pow(x, y)` / `Math.Pow(x, y)` raises `x` to the power `y` and is identical to `^` (they share one implementation): an integer exponent of magnitude up to ~9.2e18 uses exact arithmetic (so `2 ^ 10` is exactly `1024` and `10 ^ 27` is exact), while a fractional exponent (`2 ^ 0.5`) or an astronomically large integer exponent is a 34-digit approximation. Prefer `^` for ordinary powers; use `pow`/`Math.Pow` when a Math-member style is specifically wanted or the formula naturally calls for it.
- `atan2(y, x)` / `Math.Atan2(y, x)` is the two-argument arctangent in standard `atan2(y, x)` order (`y` first, then `x`).

Single-argument logarithms:
- `ln(x)` / `Math.Ln(x)` is the natural logarithm (base e).
- `lg(x)` / `Math.Lg(x)` is the base-10 logarithm.

`round` always takes two arguments: `round(x, digits)` / `Math.Round(x, digits)`. `digits` is the integer number of digits after the decimal point and must be `>= 0`; use `0` for integer rounding. Midpoints round away from zero, so `round(1.225, 2)` is `1.23`.

Use `random(start, end)` / `Math.Random(start, end)` for decimal random numbers and `randomInt(start, end)` / `Math.RandomInt(start, end)` for whole-number random values (uniform; bounds must be whole numbers within `±1e34`). Both produce values in the half-open range `[start; end)`, meaning `start <= value < end`.
Examples: `random(0, 1)` gives a decimal value where `0 <= value < 1`; `randomInt(1, 7)` gives an integer-like dice roll from `1` through `6`.
Always provide both bounds. Do not generate bare or empty-call forms such as `random`, `random()`, `Math.Random`, `Math.Random()`, `Math.RandomInt`, or `Math.RandomInt()`, and do not generate old spellings such as `Math.Rand`, `Math.Rand()`, or `Math.RandInt`.

Keep ONE Math spelling style within the same generated program — all lowercase aliases, all qualified `Math.X`, or all opened PascalCase names — never mixed.

# 14. open, load, and visibility

Place the `open` declaration before all property definitions and output — even when opening a sibling library defined later in the same algorithm (the forward reference still resolves). An `open` after any property or output is a parse error. Use `open` sparingly.

Each algorithm may have at most one `open` declaration. Multiple open targets use one comma-separated declaration: `open A, B, C`. String targets use single quotes only: `open 'url', A`. The first target must begin on the same line as `open`; a comma (trailing or leading) may continue the list across lines, and a leading dot may continue a dotted target (`open A` newline `.B` is `open A.B`), but plain newline adjacency never continues `open`. Never generate `open A ; B`, `open A B`, repeated `open` lines in one algorithm, spread in open targets (`open A*, B` is invalid), or double-quoted strings.

`open` imports public properties from the target. Ownership-first lookup applies:
1. local properties
2. parent chain
3. opened public properties

Local and parent-scope names win over opened names. If two opened providers export the same bare name, bare lookup is ambiguous and is an error — qualify the reference or open only one provider:
    open A, B
    X                    # error: Ambiguous open 'X': provided by A, B
Prefer a qualified reference such as `A.X`, or open only the provider you need.

`open` imports only public/exported members; in an `open Lib.Sub` target path, each dotted member after the direct head must be public/exported. Ordinary structural dot-access is more permissive — `Lib.UseHelper` may reach a private self-contained structural member:
    Lib = {
        UseHelper = x + 1
    }
    Lib.UseHelper(10)    # 11
Capturing, conditional, or otherwise local-only members remain inaccessible externally even when marked `public`, so do not assume `public` on a nested helper makes it importable through `open`.

The `open` target itself only needs to be lexically visible — it may be a private property; `open` still imports only its public members:
    open Lib
    Lib = {
        public Pi = 3
    }
    Pi                   # 3

Do not put `public` on `open`. Use `public` only when the task requires exported properties or clause families for open/load use.

`load` is a compile-time module directive, not a runtime function. Single-quoted strings in `open 'url'` or `load(...)` targets are compile-time directive targets; runtime strings follow the normal string-literal rules. Valid forms:
    Lib = load('https://katlang.org/lib.kat')       # property definition
    open load('https://katlang.org/lib.kat')        # open list
    open 'https://katlang.org/lib.kat'              # shorthand for open load(...)
Rules:
- `load` requires exactly one literal single-quoted HTTPS URL.
- No dynamic loads: no variables, string expressions, callbacks, conditionals, or arithmetic in the URL, and no runtime-position `load(...)` (it is invalid as ordinary output).
- Module loading may require engine/module-loader configuration and an allowed-host policy (the default allowlist is `katlang.org`).
- Do not invent local file loading, double-quoted URLs, or runtime URL construction.
Invalid:
    Url = 'https://katlang.org/lib.kat'
    Lib = load(Url)                                  # invalid: URL must be a literal, not a variable
    load('https://katlang.org/lib.kat')              # invalid: load is not allowed as runtime output
